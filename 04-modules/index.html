04. 模块系统 ​

对应漫画

本章配套四格漫画：EP.04 模块系统（含剧情回顾、知识点拆解、坑点清单与自测题）

本章示例：server/src/ch04-modules（npm run start:ch04 → http://localhost:3004）

模块是什么 ​

模块是用 @Module() 装饰的类，是 Nest 组织应用结构的基本单位。每个应用至少有一个根模块，但真实项目会按业务域拆分成多个特性模块（Feature Module）：

text
AppModule（根模块）
 ├── UsersModule（用户域）
 ├── OrdersModule（订单域，依赖 UsersModule）
 ├── CacheModule（动态模块，可配置）
 └── AppConfigModule（全局模块，一次导入处处可用）

@Module() 接收四个核心属性：

属性作用
imports导入其他模块，获得它们 exports 出来的提供者
controllers声明本模块的控制器
providers注册本模块的提供者（由 DI 容器实例化）
exports声明哪些提供者对其他模块可见

代码实现 ​

特性模块与跨模块共享 ​

模块默认是封装的：providers 里注册的服务只能在本模块内注入。想让别的模块用，必须显式 exports：

ts
// 文件: server/src/ch04-modules/users/users.module.ts
// 特性模块：用 exports 显式声明「对外可见」的提供者，未导出的即模块私有
import { Module } from '@nestjs/common';
import { UsersService } from './users.service';
import { UsersController } from './users.controller';

@Module({
    controllers: [UsersController],
    providers: [UsersService],
    exports: [UsersService], // 关键：导出后，imports 了 UsersModule 的模块才能注入 UsersService
})
export class UsersModule {}

OrdersModule 通过 imports: [UsersModule] 获得 UsersService 的使用权，于是可以跨模块注入：

ts
// 文件: server/src/ch04-modules/orders/orders.service.ts
import { Injectable } from '@nestjs/common';
import { UsersService } from '../users/users.service';

@Injectable()
export class OrdersService {
    // 跨模块注入：因为 OrdersModule imports 了 UsersModule，且 UsersService 被导出
    constructor(private readonly usersService: UsersService) {}

    // 演示：组装订单时回查用户信息
    findAllWithUser() {
        return [
            { id: 1001, amount: 99.5, user: this.usersService.findOne(1) },
            { id: 1002, amount: 20.0, user: this.usersService.findOne(2) },
        ];
    }
}

根模块把所有特性模块装配起来：

ts
// 文件: server/src/ch04-modules/app.module.ts
// 根模块：按「特性模块」组织应用 —— 每个业务域一个目录、一个模块
import { Module } from '@nestjs/common';
import { UsersModule } from './users/users.module';
import { OrdersModule } from './orders/orders.module';
import { AppConfigModule } from './common/config.module';
import { CacheModule } from './cache/cache.module';
import { MetaController } from './meta.controller';

@Module({
    imports: [
        AppConfigModule, // 全局模块：一次导入，处处可注入
        CacheModule.forRoot({ ttl: 60 }), // 动态模块：通过静态方法传入配置
        UsersModule, // 特性模块：用户域
        OrdersModule, // 特性模块：订单域（内部依赖 UsersModule 导出的服务）
    ],
    controllers: [MetaController],
})
export class AppModule {}

动态模块：可配置的模块 ​

静态模块无法接收参数。像 ConfigModule.forRoot()、TypeOrmModule.forRoot() 这样需要传配置的模块，用的是动态模块模式——类上定义静态方法，返回 DynamicModule 对象：

ts
// 文件: server/src/ch04-modules/cache/cache.module.ts
// 动态模块：静态方法接收配置，返回 DynamicModule —— 官方可配置模块的标准写法
// （ConfigModule.forRoot、TypeOrmModule.forRoot 都是同一模式）
import { DynamicModule, Module } from '@nestjs/common';
import { CacheService } from './cache.service';
import { CACHE_OPTIONS, CacheOptions } from './cache.constants';

@Module({})
export class CacheModule {
    static forRoot(options: CacheOptions): DynamicModule {
        return {
            module: CacheModule,
            providers: [{ provide: CACHE_OPTIONS, useValue: options }, CacheService],
            exports: [CacheService],
        };
    }
}

ts
// 文件: server/src/ch04-modules/cache/cache.service.ts
import { Inject, Injectable } from '@nestjs/common';
import { CACHE_OPTIONS, CacheOptions } from './cache.constants';

@Injectable()
export class CacheService {
    // 注入动态模块传入的配置对象
    constructor(@Inject(CACHE_OPTIONS) private readonly options: CacheOptions) {}

    private readonly store = new Map<string, { value: unknown; expireAt: number }>();

    set(key: string, value: unknown) {
        this.store.set(key, { value, expireAt: Date.now() + this.options.ttl * 1000 });
    }

    get(key: string) {
        const hit = this.store.get(key);
        if (!hit || hit.expireAt < Date.now()) {
            this.store.delete(key);
            return null;
        }
        return hit.value;
    }

    // 暴露配置用于演示「配置确实从 forRoot 传了进来」
    getTtl() {
        return this.options.ttl;
    }
}

全局模块：基础设施的例外 ​

配置、日志、数据库连接这类「到处都要用」的基础设施，每次 import 太啰嗦。@Global() 标记的模块只需在根模块导入一次，它导出的提供者对所有模块可见：

ts
// 文件: server/src/ch04-modules/common/config.module.ts
// 全局模块：@Global() 标记后，只需在根模块导入一次，
// 任意模块都能直接注入它导出的提供者（适合配置、日志、数据库连接等基础设施）
import { Global, Module } from '@nestjs/common';

export const APP_CONFIG = 'APP_CONFIG';

export interface AppConfig {
    appName: string;
    version: string;
}

@Global()
@Module({
    providers: [
        {
            provide: APP_CONFIG, // 使用字符串令牌（token）作为注入标识
            useValue: { appName: 'nestjs-tutorial', version: '1.0.0' } satisfies AppConfig,
        },
    ],
    exports: [APP_CONFIG],
})
export class AppConfigModule {}

消费全局配置的控制器（注意：它所在位置没有 import AppConfigModule，依然能注入）：

ts
// 文件: server/src/ch04-modules/meta.controller.ts
// 演示端点：验证全局模块（AppConfig）与动态模块（CacheModule.forRoot）确实生效
import { Controller, Get, Inject } from '@nestjs/common';
import { APP_CONFIG, AppConfig } from './common/config.module';
import { CacheService } from './cache/cache.service';

@Controller('meta')
export class MetaController {
    constructor(
        // 全局模块导出的提供者：无需在当前模块 imports 里再次声明
        @Inject(APP_CONFIG) private readonly config: AppConfig,
        // 动态模块传入 ttl=60 后创建的 CacheService
        private readonly cacheService: CacheService,
    ) {}

    @Get('config') // GET /meta/config
    getConfig() {
        return { ...this.config, cacheTtl: this.cacheService.getTtl() };
    }
}

最佳实践与坑点 ​

  1. 按业务域划分模块，一个域一个目录（users/、orders/），模块内聚、边界清晰；
  2. exports 最小化：只导出确实需要跨模块使用的服务，其余保持模块私有；
  3. 避免循环依赖：A import B、B 又 import A 会在运行期报错，遇到时先考虑把公共部分抽成第三个模块（万不得已再用 forwardRef，见第 7 章）；
  4. 全局模块克制使用：只给真正的基础设施（配置、日志、连接池）用 @Global()，滥用会让依赖关系隐形化；
  5. 动态模块命名约定：forRoot（全局一次性配置）/ forFeature（模块内局部注册）/ register（每次调用独立配置）——官方生态都遵循这套约定。
