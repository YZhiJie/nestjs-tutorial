# EP.05 控制器与路由

> 对应正文：[05. 控制器](../docs/05-controllers/index.md) · 示例：[server/src/ch05-controllers](../server/src/ch05-controllers)

## 剧情回顾

- **第 1 格**：像素酱的 echo 路由莫名 404——它声明在 `:id` 之后被当成了参数。
- **第 2 格**：码叔讲解参数装饰器：Param、Query、Body、Headers 各取一处。
- **第 3 格**：标签君实测语义化状态码：POST 默认 201，删除成功给 204。
- **第 4 格**：码叔结案：控制器三段式——取参、调用、返回。

## 知识点拆解

### 第 1 格 · 路由匹配顺序

路由按声明顺序匹配。`@Get('echo')` 写在 `@Get(':id')` 之后，请求 `/users/echo` 会先被 `:id` 吞掉。**静态路由永远写在动态路由前面**。

### 第 2 格 · 参数装饰器

```ts
@Get(':id')
findOne(
  @Param('id') id: string,
  @Query('kw') kw: string,
  @Headers('ua') ua: string,
) {}
```

装饰器与 Express 对象一一对应：`@Param` 取路径参数、`@Query` 取查询串、`@Body` 取请求体、`@Headers` 取请求头。

### 第 3 格 · 状态码语义

`@Post()` 默认返回 201；`@Delete()` 默认 200，配 `@HttpCode(204)` 表达「成功且无内容」；`@Redirect()` 做服务端跳转。处理器返回 Promise 时 Nest 自动等待并序列化结果。

### 第 4 格 · 控制器瘦身

控制器只做取参、调服务、返回三件事。业务规则下沉服务层，才能复用与测试。

## 坑点清单

1. 注入 `@Res()` 后 Nest 标准响应流程失效，拦截器不再执行——确需底层操作时才用；
2. 业务写在控制器里无法复用，也无法脱离 HTTP 单测；
3. 所有接口随手 200，状态码语义全丢，网关与监控没法按码统计。

## 自测 3 题（含答案）

1. 为什么静态路由要写在动态路由之前？——**答案**：路由按声明顺序匹配，`echo` 声明在 `:id` 后会被当作 id 匹配。
2. POST 创建资源默认返回什么状态码？——**答案**：201 Created，由框架默认给出。
3. 控制器的职责边界是什么？——**答案**：取参、调用服务、返回结果三段式，不含业务规则。
