# EP.03 请求生命周期

> 对应正文：[03. 核心概念总览](../docs/03-overview/index.md)

## 剧情回顾

- **第 1 格**：像素酱被一长串名词劝退：模块、控制器、提供者、守卫、拦截器、管道、过滤器。
- **第 2 格**：码叔点破核心：DI 容器负责创建与装配，你只管声明依赖。
- **第 3 格**：标签君背下管线口诀「中守拦管控服拦异」，理解了顺序的意义。
- **第 4 格**：码叔给出学习路线：先构件后管线，数据与安全收尾。

## 知识点拆解

### 第 1 格 · 先看流转，再背名词

名词不用背。一个请求进站后自然把所有概念串起来：中间件 → 守卫 → 拦截器（前）→ 管道 → 控制器 → 服务 → 拦截器（后），异常过滤器全程兜底。

### 第 2 格 · DI 容器怎么工作

```ts
constructor(private users: UsersService) {}
```

你只需在构造函数声明依赖。容器在实例化时读取装饰器元数据（依赖 `emitDecoratorMetadata`），按类型找到对应实例注入。依赖显式化的直接收益：测试时可以整体替换为 mock。

### 第 3 格 · 每层的职责

- **中间件**：请求来了先做点什么（日志、请求 ID）；
- **守卫**：这个请求允许执行吗（认证、授权）；
- **拦截器**：前后加什么横切逻辑（计时、包装响应）；
- **管道**：参数合法吗，要转换吗；
- **异常过滤器**：出错了怎么优雅返回。

### 第 4 格 · 学习路线

先掌握构件（模块、控制器、提供者、DI），再掌握管线（中间件到过滤器），最后数据与安全（TypeORM、JWT）与部署收尾。

## 坑点清单

1. 把依赖注入理解成手动 `new`——错，容器负责整个生命周期；
2. 混淆守卫与中间件：守卫能读到路由元数据，中间件不能；
3. 以为拦截器先于中间件执行——实际中间件才是管线第一站。

## 自测 3 题（含答案）

1. 为什么必须开启 `emitDecoratorMetadata`？——**答案**：它让 TypeScript 在编译产物中保留类型元数据，DI 容器据此推断构造函数参数类型。
2. 守卫和中间件的本质区别是什么？——**答案**：守卫能通过 ExecutionContext 知道请求将命中哪个类与方法（可结合 Reflector 读元数据），中间件不能。
3. 异常过滤器兜底的异常范围是什么？——**答案**：管线任何一层（守卫、拦截器、管道、控制器、服务）抛出的异常。
