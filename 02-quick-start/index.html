02. 快速开始 ​

对应漫画

本章配套四格漫画：EP.02 最小可运行应用（含剧情回顾、知识点拆解、坑点清单与自测题）

本章示例：server/src/ch02-quick-start（npm run start:ch02 → http://localhost:3002）

本章目标 ​

从零手写一个最小可运行的 NestJS 应用，包含：

  • 一个入口文件 main.ts：创建应用、监听端口；
  • 一个根模块 AppModule：组织应用结构；
  • 一个控制器 AppController：响应 HTTP 请求；
  • 一个服务 AppService：承载业务逻辑。

前置准备 ​

bash
# 1. 克隆/进入本教程仓库后，安装示例项目依赖
cd server
npm install

# 2. 构建（TypeScript → JavaScript，输出到 dist/）
npm run build

示例项目的 package.json 中核心依赖：

  • @nestjs/common：装饰器与通用工具（@Module、@Controller、@Injectable 等）；
  • @nestjs/core：框架内核（NestFactory、DI 容器）；
  • @nestjs/platform-express：Express 平台适配器；
  • reflect-metadata + rxjs：装饰器元数据与响应式编程的必需依赖。

代码实现 ​

入口文件 ​

main.ts 是应用的启动入口。NestFactory.create() 以根模块为蓝本创建应用实例，随后监听端口：

ts
// 文件: server/src/ch02-quick-start/main.ts
// 第 2 章「快速开始」入口：Nest 应用的最小可运行形态
import 'reflect-metadata';
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
    // NestFactory.create 会根据根模块创建应用实例（默认使用 Express 平台）
    const app = await NestFactory.create(AppModule);
    const port = Number(process.env.PORT ?? 3002);
    await app.listen(port);
    console.log(`[ch02] quick-start listening on http://localhost:${port}`);
}

bootstrap();

根模块 ​

模块是一个用 @Module() 装饰的类。根模块是 Nest 组织应用结构的起点：

ts
// 文件: server/src/ch02-quick-start/app.module.ts
// 根模块：Nest 应用的组装入口，声明本应用拥有哪些控制器与提供者
import { Module } from '@nestjs/common';
import { AppController } from './app.controller';
import { AppService } from './app.service';

@Module({
    imports: [], // 依赖的其他模块
    controllers: [AppController], // 本模块注册的控制器（接收 HTTP 请求）
    providers: [AppService], // 本模块注册的提供者（可被注入）
})
export class AppModule {}

控制器 ​

控制器负责接收请求、返回响应。@Controller() 装饰器定义路由前缀，@Get() 等方法装饰器定义具体路由：

ts
// 文件: server/src/ch02-quick-start/app.controller.ts
// 控制器：负责接收请求、调用服务、返回响应
import { Controller, Get } from '@nestjs/common';
import { AppService } from './app.service';

@Controller() // 无前缀，路由从 / 开始
export class AppController {
    // 构造函数注入：Nest 容器会自动解析 AppService 实例
    constructor(private readonly appService: AppService) {}

    @Get() // GET /
    getHello(): string {
        return this.appService.getHello();
    }

    @Get('health') // GET /health
    getHealth() {
        return { status: 'ok' };
    }
}

服务 ​

服务用 @Injectable() 标记，表示它可以被 DI 容器管理并注入到控制器中：

ts
// 文件: server/src/ch02-quick-start/app.service.ts
// 提供者（服务）：承载业务逻辑，由 @Injectable() 标记，可被控制器注入
import { Injectable } from '@nestjs/common';

@Injectable()
export class AppService {
    getHello(): string {
        return 'Hello NestJS!';
    }
}

关键概念速览 ​

概念装饰器职责
模块 Module@Module()组织应用结构，声明控制器与提供者
控制器 Controller@Controller()接收 HTTP 请求，调用服务，返回响应
服务 Service@Injectable()承载业务逻辑，可被注入复用
入口NestFactory.create()以根模块为起点创建应用实例

最佳实践与坑点 ​

  1. import 'reflect-metadata' 必须在入口第一行：Nest 的 DI 依赖装饰器元数据，漏掉会报依赖解析错误；
  2. tsconfig.json 必须开启两个开关："experimentalDecorators": true 与 "emitDecoratorMetadata": true，否则装饰器语法与构造函数注入都无法工作；
  3. 控制器只做「接收 → 调用 → 返回」：业务逻辑下沉到 Service，控制器保持轻薄，便于测试；
  4. 端口支持环境变量覆盖：示例统一读取 process.env.PORT，方便冒烟脚本与容器部署时动态指定。
