09. 守卫 ​

对应漫画

本章配套四格漫画：EP.09 守卫与鉴权（含剧情回顾、知识点拆解、坑点清单与自测题）

本章示例：server/src/ch09-guards（npm run start:ch09 → http://localhost:3009）

守卫是什么 ​

守卫（Guard）只有一个职责：决定请求「能不能被处理」。它在中间件之后、拦截器之前执行，是实现**认证（你是谁）与授权（你能做什么）**的标准位置。

守卫实现 CanActivate 接口，返回 true 放行；返回 false 或抛出异常则拒绝（ForbiddenException → 403，UnauthorizedException → 401）。

与中间件的关键差异：守卫能访问 ExecutionContext——知道请求即将命中哪个类、哪个方法，因此可以结合 Reflector 读取路由元数据做精细化控制。

代码实现：认证 + 角色双层守卫链 ​

本章搭建一条全局守卫链：AuthGuard（认证，先执行）→ RolesGuard（授权，后执行）。

认证守卫 ​

ts
// 文件: server/src/ch09-guards/auth.guard.ts
// 守卫：实现 CanActivate，返回 false 或抛异常即拒绝请求（403/401）
// 职责定位：「该不该放行」—— 鉴权、角色、限流等；不做参数校验（那是管道的活）
import { CanActivate, ExecutionContext, Injectable, UnauthorizedException } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import type { Request } from 'express';
import { IS_PUBLIC_KEY } from './public.decorator';

// 演示用的「令牌 → 用户」映射；真实项目应验证 JWT（见第 14 章）
const TOKEN_USERS: Record<string, { id: number; name: string; role: 'admin' | 'user' }> = {
    'admin-token': { id: 1, name: 'admin', role: 'admin' },
    'user-token': { id: 2, name: 'demo', role: 'user' },
};

@Injectable()
export class AuthGuard implements CanActivate {
    constructor(private readonly reflector: Reflector) {}

    canActivate(context: ExecutionContext): boolean {
        // getAllAndOverride：路由级元数据优先，类级兜底
        const isPublic = this.reflector.getAllAndOverride<boolean>(IS_PUBLIC_KEY, [
            context.getHandler(),
            context.getClass(),
        ]);
        if (isPublic) return true;

        const request = context.switchToHttp().getRequest<Request>();
        const token = request.headers['x-demo-token'] as string | undefined;
        const user = token ? TOKEN_USERS[token] : undefined;
        if (!user) {
            throw new UnauthorizedException('缺少或非法的 x-demo-token');
        }
        // 把解析出的用户挂到请求对象上，供 RolesGuard 与控制器使用
        (request as Request & { user: unknown }).user = user;
        return true;
    }
}

角色守卫 ​

ts
// 文件: server/src/ch09-guards/roles.guard.ts
import { CanActivate, ExecutionContext, ForbiddenException, Injectable } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import type { Request } from 'express';
import { ROLES_KEY, Role } from './roles.decorator';

@Injectable()
export class RolesGuard implements CanActivate {
    constructor(private readonly reflector: Reflector) {}

    canActivate(context: ExecutionContext): boolean {
        // 路由未声明 @Roles 时视为「登录即可」
        const requiredRoles = this.reflector.getAllAndOverride<Role[]>(ROLES_KEY, [
            context.getHandler(),
            context.getClass(),
        ]);
        if (!requiredRoles || requiredRoles.length === 0) return true;

        const { user } = context.switchToHttp().getRequest<Request & { user?: { role: Role } }>();
        if (!user || !requiredRoles.includes(user.role)) {
            throw new ForbiddenException(`需要角色：${requiredRoles.join(', ')}`);
        }
        return true;
    }
}

元数据装饰器 ​

@Public() 标记公开接口，@Roles() 声明所需角色——本质都是 SetMetadata，供守卫用 Reflector 读取：

ts
// 文件: server/src/ch09-guards/public.decorator.ts
// 自定义元数据装饰器：配合全局守卫实现「默认鉴权、个别放行」
import { SetMetadata } from '@nestjs/common';

export const IS_PUBLIC_KEY = 'isPublic';

// @Public() —— 标记无需登录即可访问的路由
export const Public = () => SetMetadata(IS_PUBLIC_KEY, true);

注册为全局守卫链 ​

APP_GUARD 令牌把守卫注册为全局生效，注册顺序即执行顺序：

ts
// 文件: server/src/ch09-guards/app.module.ts
// APP_GUARD：把守卫注册为全局守卫（顺序即执行顺序：先 Auth 后 Roles）
// 对比：@UseGuards() 是局部绑定（路由级 / 控制器级）
import { Module } from '@nestjs/common';
import { APP_GUARD } from '@nestjs/core';
import { AuthGuard } from './auth.guard';
import { RolesGuard } from './roles.guard';
import { UsersController } from './users.controller';

@Module({
    controllers: [UsersController],
    providers: [
        { provide: APP_GUARD, useClass: AuthGuard },
        { provide: APP_GUARD, useClass: RolesGuard },
    ],
})
export class AppModule {}

控制器 ​

ts
// 文件: server/src/ch09-guards/users.controller.ts
import { Controller, Get, Req } from '@nestjs/common';
import type { Request } from 'express';
import { Public } from './public.decorator';
import { Roles } from './roles.decorator';

@Controller()
export class UsersController {
    // GET /public —— @Public() 放行，无需令牌
    @Public()
    @Get('public')
    getPublic() {
        return { message: '公开接口，无需令牌' };
    }

    // GET /profile —— 全局 AuthGuard 生效：需要合法令牌
    @Get('profile')
    getProfile(@Req() req: Request & { user: unknown }) {
        return { user: req.user };
    }

    // GET /admin —— 叠加 RolesGuard：需要 admin 角色
    @Roles('admin')
    @Get('admin')
    getAdmin() {
        return { message: '管理员专属数据' };
    }
}

最佳实践与坑点 ​

  1. 职责单一：守卫只回答「放行与否」，参数格式校验交给管道（第 11 章），业务规则放服务层；
  2. getAllAndOverride vs get：前者路由级元数据优先、类级兜底（最常用）；后者只取第一个命中项；
  3. 全局守卫 + @Public() 放行的组合是认证体系的标准模式——默认全部受保护，显式声明公开接口，避免「忘了加守卫导致接口裸奔」；
  4. 守卫间通过 request.user 传递数据：AuthGuard 解析出的用户挂载到请求对象，下游 RolesGuard 与控制器直接取用；
  5. 真实项目用 JWT 替换静态令牌表：本章为聚焦守卫机制做了简化，完整 JWT 认证见第 14 章。
