NestJS 是什么 ​

NestJS 是一个用于构建高效、可扩展的服务端应用的 Node.js 框架。它使用 TypeScript 构建（同时兼容纯 JavaScript），结合了三种编程范式：

  • 面向对象编程（OOP）：控制器、服务、模块都是类，职责边界清晰；
  • 函数式编程（FP）：拦截器、管道大量运用 RxJS 与纯函数思想；
  • 函数响应式编程（FRP）：RxJS 是一等公民，流式处理贯穿框架。

NestJS 默认基于 Express 作为底层 HTTP 平台，也可以一行代码切换到 Fastify。框架在此之上提供了一套开箱即用的应用架构——如果你用过 Angular，会发现模块、依赖注入、装饰器这些概念几乎一模一样。

为什么选择 NestJS ​

痛点NestJS 的解法
Express/Koa 自由度过高，项目结构因人而异提供「约定优于配置」的标准架构：模块 + 控制器 + 提供者
JavaScript 大型项目缺乏类型约束全面拥抱 TypeScript，装饰器元数据驱动依赖注入
横切关注点（鉴权、日志、校验）散落各处提供守卫、拦截器、管道、异常过滤器四大利器
依赖关系靠手动 new，测试困难内置 IoC 容器，构造函数声明依赖，mock 替换轻而易举
微服务、WebSocket、GraphQL 各自为政同一套编程模型覆盖 HTTP、WebSocket、微服务、GraphQL、CQRS

核心特性一览 ​

  • 模块化架构：应用由模块（@Module）组成，支持静态模块、动态模块、全局模块；
  • 依赖注入（DI）：内置 IoC 容器，支持单例 / 瞬态 / 请求级三种作用域；
  • 请求处理管线：中间件 → 守卫 → 拦截器 → 管道 → 控制器 → 异常过滤器，职责分明；
  • 装饰器驱动：@Get()、@Post()、@Injectable()、@UseGuards() 等声明式 API；
  • 生态系统：@nestjs/typeorm、@nestjs/jwt、@nestjs/config 等官方模块开箱即用；
  • CLI 工具：@nestjs/cli 提供项目生成、代码脚手架、构建能力。

两种搭建项目的方式 ​

方式一：Nest CLI（官方推荐） ​

bash
npm i -g @nestjs/cli
nest new my-nest-app

2

CLI 会生成完整项目骨架（含 ESLint、Prettier、Jest），并提供代码生成器：

bash
nest g module users      # 生成模块
nest g controller users  # 生成控制器
nest g service users     # 生成服务

方式二：手动搭建（本教程示例项目采用） ​

为了让你看清 Nest 应用的最小必需结构，本教程的配套示例项目没有使用 CLI 生成器，而是手工编写每个文件。一个 Nest 应用最少只需要：

  1. main.ts —— 入口文件，用 NestFactory 创建应用并监听端口；
  2. 一个根模块 app.module.ts —— 组织应用结构；
  3. 至少一个控制器或服务 —— 处理业务；
  4. tsconfig.json —— 必须开启 experimentalDecorators 与 emitDecoratorMetadata（装饰器与 DI 的基石）。

下一章我们将从零手写这四个文件，并把第一个应用跑起来。

本教程的组织方式 ​

  • 每章聚焦一个主题，先讲概念，再给完整可运行代码，最后给出 curl 验证命令与真实期望输出；
  • 文档中所有代码块都通过 VitePress 的代码片段导入功能直接引用示例项目源文件，保证文档与代码零偏差；
  • 每章示例在 server/src/chXX-* 目录下，端口为 3000 + 章节号（如第 5 章为 3005）。
