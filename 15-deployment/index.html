15. 部署 ​

对应漫画

本章配套四格漫画：EP.15 生产部署（含剧情回顾、知识点拆解、坑点清单与自测题）

本章示例：server/src/ch15-deployment（npm run start:ch15 → http://localhost:3015）

本章说明 ​

把 Nest 应用推向生产，需要补齐四块拼图：

  1. 配置管理：环境变量 → 带类型的配置对象，非法配置在启动期直接失败（fail fast）；
  2. 优雅关闭：收到 SIGTERM/SIGINT 时先停止接收新请求、执行清理钩子，再退出进程；
  3. 健康检查：为负载均衡/容器编排提供存活探针；
  4. 容器化：多阶段 Dockerfile，镜像只保留运行所需产物。

代码实现 ​

配置校验（fail fast） ​

@nestjs/config 的 ConfigModule.forRoot({ validate }) 支持自定义校验函数——启动时把环境变量解析成带类型的配置对象，非法配置直接抛错拒绝启动，而不是运行到一半才炸：

ts
// 文件: server/src/ch15-deployment/config/configuration.ts
// 配置校验：应用启动时就把环境变量解析成带类型的配置对象，
// 非法配置在「启动期」直接失败（fail fast），而不是运行到一半才炸
export interface AppConfig {
    NODE_ENV: 'development' | 'test' | 'production';
    PORT: number;
    LOG_LEVEL: 'debug' | 'info' | 'warn' | 'error';
}

export function validate(config: Record<string, unknown>): AppConfig {
    const env = (config.NODE_ENV as string) ?? 'development';
    if (!['development', 'test', 'production'].includes(env)) {
        throw new Error(`NODE_ENV 非法：${env}（允许 development/test/production）`);
    }

    const port = Number(config.PORT ?? 3015);
    if (!Number.isInteger(port) || port <= 0 || port > 65535) {
        throw new Error(`PORT 非法：${config.PORT}`);
    }

    const level = (config.LOG_LEVEL as string) ?? 'info';
    if (!['debug', 'info', 'warn', 'error'].includes(level)) {
        throw new Error(`LOG_LEVEL 非法：${level}`);
    }

    return { NODE_ENV: env as AppConfig['NODE_ENV'], PORT: port, LOG_LEVEL: level as AppConfig['LOG_LEVEL'] };
}

模块装配与健康检查控制器：

ts
// 文件: server/src/ch15-deployment/app.module.ts
import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';
import { validate } from './config/configuration';
import { HealthController } from './health.controller';

@Module({
    imports: [
        ConfigModule.forRoot({
            isGlobal: true, // 全局可注入 ConfigService
            envFilePath: ['.env'], // 读取 server/.env（不存在时使用进程环境变量）
            validate, // 启动期校验环境变量，非法即启动失败
        }),
    ],
    controllers: [HealthController],
})
export class AppModule {}

// 文件: server/src/ch15-deployment/health.controller.ts
// 健康检查端点：负载均衡器 / K8s liveness & readiness 探针使用
import { Controller, Get } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';

@Controller('health')
export class HealthController {
    constructor(private readonly config: ConfigService) {}

    @Get()
    check() {
        return {
            status: 'ok',
            env: this.config.get<string>('NODE_ENV'),
            logLevel: this.config.get<string>('LOG_LEVEL'),
            uptime: Math.round(process.uptime() * 100) / 100,
            timestamp: new Date().toISOString(),
        };
    }
}

优雅关闭 ​

app.enableShutdownHooks() 让框架监听系统信号：收到 SIGTERM 时先停止接收新连接，等待进行中的请求完成并执行 onModuleDestroy 钩子，再退出进程——这是 K8s 滚动发布不断流的必需能力：

ts
// 文件: server/src/ch15-deployment/main.ts
// 第 15 章「部署」入口：配置校验 + 优雅关闭
import 'reflect-metadata';
import { NestFactory } from '@nestjs/core';
import { ConfigService } from '@nestjs/config';
import { AppModule } from './app.module';

async function bootstrap() {
    const app = await NestFactory.create(AppModule);

    // 优雅关闭：收到 SIGTERM/SIGINT 时先停止接收新请求、执行 onModuleDestroy，
    // 再退出进程 —— 容器编排（K8s）滚动发布时的必需能力
    app.enableShutdownHooks();

    const config = app.get(ConfigService);
    const port = config.get<number>('PORT', 3015);
    await app.listen(port);
    console.log(`[ch15] deployment listening on http://localhost:${port} (env=${config.get('NODE_ENV')})`);
}

bootstrap();

容器化部署 ​

配套的多阶段 Dockerfile（位于 server/Dockerfile）：

# 文件: server/Dockerfile
# 多阶段构建：第一阶段编译，第二阶段只保留运行所需产物
FROM node:22-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --no-audit --no-fund
COPY tsconfig.json tsconfig.build.json nest-cli.json ./
COPY src ./src
RUN npm run build

FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
# 只安装生产依赖，镜像更小、攻击面更小
COPY package.json package-lock.json ./
RUN npm ci --omit=dev --no-audit --no-fund
COPY --from=builder /app/dist ./dist
EXPOSE 3015
# 默认启动第 15 章示例；其他章节改 CMD 中的路径即可
CMD ["node", "dist/ch15-deployment/main.js"]

多阶段构建的收益：第一阶段（builder）包含 TypeScript、CLI 等编译依赖；第二阶段（runner）只拷贝 dist 产物并安装生产依赖（npm ci --omit=dev）——镜像体积与攻击面都显著缩小。

生产部署检查清单 ​

项目检查点
配置密钥/连接串全部走环境变量；validate 启动校验开启
数据库synchronize: false，结构变更走 migrations
日志结构化日志（JSON），按级别输出，接入采集系统
关闭enableShutdownHooks() 开启；onModuleDestroy 释放连接池
容器多阶段构建；--omit=dev；非 root 用户运行（可再加 USER node）
编排配置 /health 存活探针；滚动发布配合优雅关闭

最佳实践与坑点 ​

  1. fail fast 优于运行期报错：配置错误在启动第一秒暴露，而不是半夜流量高峰时才炸；
  2. enableShutdownHooks() 有平台前提：它依赖 Node 能收到信号——直接 kill -9 无法触发（也没法救），编排系统默认发 SIGTERM 所以没问题；
  3. Docker 构建上下文要配 .dockerignore：排除 node_modules、dist、.git（本仓库 server/.dockerignore 已配置），否则镜像构建又慢又大；
  4. 端口不要写死在 CMD：容器内读 PORT 环境变量，编排系统才能灵活分配；
  5. 健康检查接口要轻：只报进程状态，不要在探针里查数据库（否则 DB 抖动会误杀所有实例）；就绪探针另议。
