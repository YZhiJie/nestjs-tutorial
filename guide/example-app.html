示例工程怎么跑 ​

示例工程的启动方式、接口清单与常见问题排查。

示例工程在 apps/api，与文档同仓库。文档里的代码片段全部从它导入，所以你看到的代码一定能在本地跑起来。

环境要求 ​

依赖版本要求说明
Node.js>= 22.12.0测试工具链（Vitest 5）要求 22.12 以上；NestJS 12 自身要求 >= 20
pnpm10.x仓库声明 packageManager: pnpm@10.15.0，用 Corepack 可直接对齐
Docker能运行 docker compose用来起本地 Postgres；只想跑测试时不需要
bash
node -v
pnpm -v
docker compose version

启动 ​

bash
# 1. 安装依赖（根目录执行，workspace 会一起装）
pnpm install

# 2. 起本地 Postgres 与 Redis（容器名 nestjs-tutorial-postgres / nestjs-tutorial-redis）
docker compose up -d postgres redis
docker compose ps --format '{{.Name}} {{.Health}}'   # 等到 healthy

# 3. 准备环境变量
cp apps/api/.env.example apps/api/.env

# 4. 建表 + 写入演示账号与商品（两条命令都是幂等的）
pnpm --filter @nestjs-tutorial/api db:migrate
pnpm seed

# 5. 启动开发模式（watch）
pnpm dev

启动成功的标志是日志里出现：

text
[Bootstrap] API 已启动: http://localhost:3000/api
[Bootstrap] 数据库: postgres (localhost:5432/nestjs_tutorial)
[Bootstrap] 缓存: redis (localhost:6379)，队列: redis

默认使用 Postgres 与 Redis，不会静默降级

DB_DRIVER 默认是 postgres。数据库连不上时进程会以退出码 1 结束，并打印排查步骤，不会自动切到内存库。

缓存与队列默认跟随数据库：Postgres 模式使用 Redis，连不上同样退出码 1；sqljs 模式自动使用进程内实现。只想跑接口、不需要分布式缓存与队列时，显式设置：

bash
CACHE_DRIVER=memory QUEUE_DRIVER=memory pnpm dev

测试（pnpm test / pnpm test:e2e）会自动使用 sqljs + 内存缓存/队列，因此 CI 不需要 Docker。

关键接口 ​

方法路径鉴权用途
GET/api/health公开健康检查（数据库/缓存不可用时 degraded）
GET/api/health/ready公开就绪检查（数据库或缓存不可用时 503）
POST/api/auth/login公开登录，返回访问令牌 + 刷新令牌
POST/api/auth/refresh公开（需刷新令牌）轮换刷新令牌
POST/api/auth/logout需登录吊销当前会话的刷新令牌，返回 204
GET/api/auth/me需登录当前用户信息
GET/api/users?page=1&pageSize=20admin用户列表，支持 search
POST/api/usersadmin创建用户
GET/api/users/:id登录（非 admin 只能读自己）用户详情
PATCH/api/users/:idadmin更新用户
DELETE/api/users/:idadmin软删除，返回 204
GET/api/audits?limit=50admin审计日志（含操作人姓名，命中缓存时 x-cache: hit）
POST/api/jobs/refresh-tokens-cleanupadmin手动触发刷新令牌清理任务，返回 202 + 任务 id
POST/api/jobs/order-timeout-sweepadmin手动触发超时关单（pending 超过 30 分钟未支付则取消并回补库存）
GET/api/jobs/:idadmin查询任务状态与执行结果
GET/api/bff/dashboard?client=web需登录（client=admin 仅 admin）按端聚合用户、审计、订单摘要与下游通知；x-cache 表示聚合缓存
GET/api/mock/notifications?userId=...公开（仅示例用）下游通知服务 mock，可注入延迟与 5xx
GET/api/products公开商品目录与可售库存
PATCH/api/products/:id/inventoryadmin库存盘点，直接设定可售量
POST/api/orders需登录，必须带 Idempotency-Key下单；首次 201，幂等重放 200（idempotent-replay: true）
GET/api/orders?page=1&pageSize=20需登录订单列表；非 admin 只能看自己，支持 status 过滤
GET/api/orders/:id本人或 admin订单详情
POST/api/orders/:id/pay本人或 admin模拟支付：pending → paid
POST/api/orders/:id/cancel本人或 admin取消：pending → cancelled 并回补库存
POST/api/orders/:id/shipadmin发货：paid → shipped
POST/api/orders/:id/complete本人或 admin确认收货：shipped → completed
GET/api/realtime/events需登录SSE 事件流；?room=orders 仅 admin，支持 Last-Event-ID 续传
GET/api/realtime/statsadmin实时连接快照：连接数、房间分布、事件序号
POST/api/files需登录multipart 上传（字段名 file，默认上限 2MB），返回 sha256 与下载地址
GET/api/files/:id本人或 admin下载文件，响应头含 x-content-sha256，强制 attachment
POST/api/webhooks/payments公开（HMAC 签名）支付回调；需 x-webhook-signature 与 x-webhook-timestamp，事件 ID 幂等

用 curl 验证一遍 ​

bash
# 1. 健康检查（公开）
curl -s http://localhost:3000/api/health

# 2. 登录，取访问令牌
TOKEN=$(curl -s -X POST http://localhost:3000/api/auth/login \
  -H 'content-type: application/json' \
  -d '{"email":"ada@example.com","password":"Passw0rd!"}' | jq -r .data.accessToken)

# 3. 不带令牌：401 AUTH_REQUIRED
curl -s http://localhost:3000/api/users

# 4. 带令牌分页（种子数据 3 条）
curl -s "http://localhost:3000/api/users?page=1&pageSize=2" \
  -H "authorization: Bearer $TOKEN"

# 5. 创建用户
curl -s -X POST http://localhost:3000/api/users \
  -H "authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"email":"demo@example.com","name":"Demo User","password":"Passw0rd!"}'

# 6. 触发校验失败（观察统一错误结构）
curl -s -X POST http://localhost:3000/api/users \
  -H "authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"email":"bad","name":"X"}'

# 7. 审计日志（注意响应头 x-cache：第一次 miss，第二次 hit）
curl -s -D - "http://localhost:3000/api/audits?limit=2" \
  -H "authorization: Bearer $TOKEN" -o /dev/null | grep -i '^x-cache'

# 8. 手动触发刷新令牌清理任务，再查状态
JOB_ID=$(curl -s -X POST http://localhost:3000/api/jobs/refresh-tokens-cleanup \
  -H "authorization: Bearer $TOKEN" | jq -r .data.id)
curl -s "http://localhost:3000/api/jobs/$JOB_ID" \
  -H "authorization: Bearer $TOKEN"

# 9. BFF 聚合：连续两次，第二次 x-cache: hit
curl -s -D - "http://localhost:3000/api/bff/dashboard?client=admin" \
  -H "authorization: Bearer $TOKEN" -o /dev/null | grep -i '^x-cache'

# 10. 下游超时：HTTP 仍是 200，通知块降级
curl -s "http://localhost:3000/api/bff/dashboard?client=web&simulate=notifications-timeout" \
  -H "authorization: Bearer $TOKEN" | jq -c '.data | {partial: .meta.partial, notifications: .notifications.status}'

# 11. 商品目录（公开），取一个商品 id
PRODUCT_ID=$(curl -s http://localhost:3000/api/products \
  | jq -r '.data[] | select(.sku=="KB-MECH-01") | .id')

# 12. 下单：必须带 Idempotency-Key，首次 201，同键重放 200
ORDER_KEY="demo-$(date +%s)"
ORDER_ID=$(curl -s -X POST http://localhost:3000/api/orders \
  -H "authorization: Bearer $TOKEN" -H "idempotency-key: $ORDER_KEY" \
  -H 'content-type: application/json' \
  -d "{\"items\":[{\"productId\":\"$PRODUCT_ID\",\"quantity\":2}]}" | jq -r .data.order.id)
curl -s -D - -o /dev/null -X POST http://localhost:3000/api/orders \
  -H "authorization: Bearer $TOKEN" -H "idempotency-key: $ORDER_KEY" \
  -H 'content-type: application/json' \
  -d "{\"items\":[{\"productId\":\"$PRODUCT_ID\",\"quantity\":2}]}" \
  | grep -i '^idempotent-replay'

# 13. 非法状态迁移：pending 直接完成 → 409 ORDER_INVALID_TRANSITION
curl -s -X POST http://localhost:3000/api/orders/$ORDER_ID/complete \
  -H "authorization: Bearer $TOKEN" | jq -c '.error'

# 14. 并发零超卖：20 个请求抢 5 件库存，期望 5 成功 / 15 个 409 / 最终库存 0
pnpm --filter @nestjs-tutorial/api demo:oversell

# 15. SSE：一个终端订阅（保持不关），另一个终端下单，1 秒内收到 order.created
curl -sN -H "authorization: Bearer $TOKEN" http://localhost:3000/api/realtime/events

# 16. 实时连接统计（另开终端执行）
curl -s -H "authorization: Bearer $TOKEN" http://localhost:3000/api/realtime/stats

# 17. 上传并下载（PNG 需为真实图片文件）
UPLOAD=$(curl -s -F 'file=@pixel.png;type=image/png' \
  -H "authorization: Bearer $TOKEN" http://localhost:3000/api/files)
FILE_ID=$(printf '%s' "$UPLOAD" | jq -r .data.id)
curl -s -D - -o downloaded.png -H "authorization: Bearer $TOKEN" \
  "http://localhost:3000/api/files/$FILE_ID" | grep -iE 'content-disposition|x-content-sha256'

# 18. 支付回调：按 timestamp.rawBody 算 HMAC，重复投递同一事件得到 duplicate: true
SECRET='dev-only-insecure-webhook-secret-change-me'
BODY='{"id":"evt_demo_1","type":"payment.succeeded","data":{"orderId":"o-1","amountCents":100}}'
TS=$(date +%s)
SIG="sha256=$(printf '%s' "$TS.$BODY" | openssl dgst -sha256 -hmac "$SECRET" | awk '{print $2}')"
curl -s -X POST http://localhost:3000/api/webhooks/payments \
  -H 'content-type: application/json' -H "x-webhook-timestamp: $TS" \
  -H "x-webhook-signature: $SIG" -d "$BODY"

bash

命令作用
pnpm --filter @nestjs-tutorial/api lintESLint，警告数也会导致失败（--max-warnings=0）
pnpm --filter @nestjs-tutorial/api typechecktsc --noEmit，含测试文件
pnpm --filter @nestjs-tutorial/api testVitest 单元测试（sqljs，无需 Docker）
pnpm --filter @nestjs-tutorial/api test:e2eVitest + supertest 端到端测试（sqljs）
pnpm --filter @nestjs-tutorial/api buildnest build 输出到 dist/
pnpm docs:buildVitePress 静态构建，链接错误会导致失败

CI 把上述命令按 lint → typecheck → 单测 → e2e → 构建 → 文档构建 顺序执行，配置在 .github/workflows/ci.yml；测试使用 sqljs 与内存缓存/队列，不需要 Postgres/Redis 容器。

文档与示例的关系 ​

文档里引用代码的写法：

md
<<< ../../../apps/api/src/main.ts{ts}

路径相对当前 Markdown 文件；{ts} 显式指定语言，保证高亮正确。因为指向的是真实文件，改代码后文档自动同步——这也是本仓库不写「代码副本」的原因。

只引用某个方法时用 region：

md
<<< ../../../apps/api/src/users/users.service.ts#users-service-create-transaction{ts}

常见启动问题 ​

现象原因处理
✖ 数据库连接失败，服务未启动。Postgres 没起，或 DB_* 配置不对按提示执行 docker compose up -d postgres，检查 apps/api/.env
✖ Redis 连接失败，服务未启动。Redis 没起，或 REDIS_* 配置不对docker compose up -d redis；或临时用 CACHE_DRIVER=memory QUEUE_DRIVER=memory
审计列表一直是 x-cache: miss有写操作在持续让缓存失效，或缓存驱动是 memory停止写入后连续请求两次；检查启动日志的 缓存: 一行
Cannot find module '.../user.entity'ESM 下相对导入必须带 .js 后缀把 ./user.entity 改成 ./user.entity.js
ReferenceError: Cannot access 'X' before initialization两个类文件互相 import，装饰器元数据在初始化前被求值见 第 02 章 的「循环依赖」一节
ERR_REQUIRE_ESM用了 Jest 等只支持 CommonJS 的测试器NestJS 12 是纯 ESM，测试请用 Vitest
端口占用 EADDRINUSE3000 被占PORT=3001 pnpm dev
环境变量校验失败PORT 等变量类型不对检查 apps/api/.env，规则见 第 05 章
登录返回 401 AUTH_INVALID_CREDENTIALS没跑种子脚本，或密码不对pnpm seed，统一密码 Passw0rd!
接口一直 401没带 Authorization: Bearer <token>，或令牌已过期重新登录；刷新逻辑见 第 06 章
relation "users" does not exist没执行迁移pnpm --filter @nestjs-tutorial/api db:migrate
上传返回 413 FILE_TOO_LARGE文件超过 FILES_MAX_SIZE_BYTES（默认 2MB）换小文件，或调大环境变量（传输层硬上限 5MB）
回调一直 401 WEBHOOK_SIGNATURE_INVALID签名不是按 timestamp.rawBody 算的，或请求体被改写用原始 JSON 字符串计算 HMAC，别先反序列化再拼
