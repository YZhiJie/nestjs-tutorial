07 容器网络、端口映射与数据卷 ​

端口映射链路、自定义 bridge 网络与服务名 DNS、EXPOSE 与 ports 的区别，以及命名卷与 bind mount 的语义。

本章目标 ​

读完并动手做完本章，你应该能：

  1. 画出「宿主机 → 端口映射 → 容器网络 → 服务名 DNS」的完整链路；
  2. 用自定义 bridge 网络做服务隔离，解释为什么不同网络的容器互相解析不到；
  3. 说清 EXPOSE、ports、docker run -p 三者的区别，避免把「镜像声明了端口」误当成「宿主机能访问」；
  4. 区分命名卷与 bind mount 的语义，知道数据在 down、down -v、容器删除后的去向；
  5. 用 docker network inspect、docker volume inspect 验证「我以为的配置」和「实际生效的配置」是否一致。

概念与原理 ​

容器有自己的网络命名空间 ​

每个容器有独立的网卡、IP、路由表和 localhost。所以：

  • 容器里的 127.0.0.1 是容器自己，不是宿主机；
  • 容器里的 localhost:5432 不会连到宿主机的 Postgres；
  • 两个容器即使在同一台机器上，也要通过 bridge 网络或端口映射通信。

compose 默认会为项目创建一个 bridge 网络，服务名就是 DNS 名。例如 client 访问 http://api:3000，Docker 的内嵌 DNS（通常监听 127.0.0.11）把 api 解析成容器 IP。

自定义网络才是隔离边界 ​

compose 里声明两个网络：

yaml
networks:
  frontend:
  backend:

只有同时接入两个网络的服务才能跨过去。本章示例：

text
frontend: web, client, outsider
backend:  api, client

client  → 可以访问 api 与 web
outsider → 只能访问 web，访问 api 得到 ENOTFOUND

这比「用防火墙规则限制 IP」更清晰：网络成员关系就是权限边界，容器 IP 变了也不影响。

EXPOSE 不是端口映射 ​

写法作用宿主机能否访问
Dockerfile EXPOSE 3000声明「这个镜像默认监听 3000」，写入元数据不能
compose ports: ['127.0.0.1:18081:80']在宿主机开端口并转发到容器能，且只绑回环地址
docker run -p 8080:80同上，命令行形式能
compose 不写 ports只在容器网络内可达不能

docker compose ps 的 PORTS 列里，只有出现 宿主机地址:宿主机端口->容器端口 才是发布；单独一个 3000/tcp 只是 EXPOSE 的展示。

端口映射的两个方向 ​

text
宿主机 18081  ──转发──▶  容器 80

冒号左边是宿主机，右边是容器。写反了不会报错，只会「访问不到」：

  • '127.0.0.1:18081:80'：只允许本机访问，适合开发；
  • '18081:80'：绑定所有网卡，同网段的人也能访问，开发环境慎用；
  • '80:18081'：把宿主机的 80 转到容器的 18081，大概率不是你要的。

命名卷与 bind mount 的语义不同 ​

维度命名卷（named volume）bind mount
数据位置Docker 管理的虚拟磁盘目录你指定的宿主机路径
生命周期独立于容器，down 默认保留完全由宿主机文件系统决定
首次挂载空卷会把镜像里同路径的内容复制进来直接覆盖，镜像内容看不到
适合数据库、上传文件、需要备份的数据开发时挂源码、挂配置文件
删除docker volume rm / down -vrm -rf 宿主机目录

本章的 writer / reader 用命名卷共享文件：writer 写完后容器退出，reader 仍然能读到。因为卷不属于任何一个容器。

最小可跑示例 ​

一、网络拓扑与 compose ​

yml
# 07 章：自定义网络隔离 + 端口映射 + 命名卷共享。
# 启动：docker compose -f examples/docker/07-network-volume/compose.yaml up -d --build
# 网络拓扑：
#   frontend: web, client, outsider
#   backend:  api, client
#   client 同时接入两个网络，能访问 api 与 web；outsider 只在前端网络，解析不到 api。
services:
  web:
    image: nginx:1.27-alpine
    ports:
      # 只绑回环地址：同网段的人无法直接访问你的开发服务
      - '127.0.0.1:18081:80'
    volumes:
      # bind mount：宿主机改文件，容器里立刻可见
      - ./web:/usr/share/nginx/html:ro
    networks:
      - frontend

  api:
    build:
      context: ./api
    image: docker-guide/07-network-volume-api:local
    # 注意：没有 ports，宿主机无法直接访问；只能被同网络容器通过服务名访问
    networks:
      - backend
    healthcheck:
      test:
        - CMD
        - node
        - -e
        - "fetch('http://127.0.0.1:3000/healthz').then((r)=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"
      interval: 5s
      timeout: 3s
      retries: 5
      start_period: 2s

  client:
    image: node:24-alpine
    # 常驻进程，方便后面 docker compose exec 进去做连通性测试
    command: ['node', '-e', 'setInterval(() => {}, 1000000)']
    networks:
      - frontend
      - backend
    depends_on:
      api:
        condition: service_healthy
      web:
        condition: service_started

  outsider:
    image: node:24-alpine
    # outsider 只接 frontend，用来验证「网络隔离」不是口号
    command: ['node', '-e', 'setInterval(() => {}, 1000000)']
    networks:
      - frontend

  writer:
    image: node:24-alpine
    profiles: ['volume']
    volumes:
      - appdata:/data
    command:
      - node
      - -e
      - |
        const fs = require('node:fs');
        fs.writeFileSync('/data/greeting.txt', 'hello from writer\n');
        console.log('writer 写入 /data/greeting.txt');

  reader:
    image: node:24-alpine
    profiles: ['volume']
    volumes:
      - appdata:/data
    command:
      - node
      - -e
      - |
        const fs = require('node:fs');
        console.log('reader 读到:', fs.readFileSync('/data/greeting.txt', 'utf8').trim());

networks:
  frontend:
  backend:

volumes:
  # 命名卷由 Docker 管理，容器删了数据还在
  appdata:

api 的镜像很小，只做健康检查和返回主机名：

dockerfile
# 07 章演示 API 镜像：零依赖，构建很快。
FROM node:24-alpine
WORKDIR /app
COPY server.mjs ./server.mjs
RUN addgroup -S app && adduser -S app -G app
USER app
EXPOSE 3000
HEALTHCHECK --interval=5s --timeout=3s --start-period=2s --retries=5 \
  CMD node -e "fetch('http://127.0.0.1:3000/healthz').then((r)=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"
CMD ["node", "server.mjs"]

bash
docker compose -f examples/docker/07-network-volume/compose.yaml up -d --build
bash examples/docker/07-network-volume/scripts/network-check.sh

本机真实输出：

== 4. outsider（只在前端网络）访问 api，预期失败 ==

== 6. 网络与 IP ==

== 7. 命名卷：writer 写，reader 读 ==

两个关键结果：

  • outsider 得到 ENOTFOUND，说明它根本解析不到 api，不是「连上了被拒绝」；
  • docker compose port api 3000 输出 :0，说明没有发布到宿主机。

三、看实际的网络成员 ​

bash
docker network inspect 07-network-volume_backend \
  --format '{{range .Containers}}{{.Name}} {{.IPv4Address}}{{"\n"}}{{end}}'

本机输出类似：

text
07-network-volume-api-1 172.23.0.2/16
07-network-volume-client-1 172.23.0.3/16

outsider 不在这个列表里，所以它解析不到 api。

逐步拆解 ​

第 1 步：先分清「服务名」与「容器名」 ​

  • 服务名来自 compose 的 key（api、web、client），应该用它做 DNS；
  • 容器名是 07-network-volume-api-1 这类自动生成的名称，会随项目名变化；
  • 手动 docker run --name foo 的容器，只有在同一自定义网络里才能互相解析。

不要硬编码容器 IP。容器重建后 IP 会变，服务名不变。

第 2 步：为什么 api 不写 ports ​

api 只需要被 client 访问，不需要暴露给宿主机。不写 ports 有三个好处：

  1. 宿主机不占端口，不会和本地 pnpm dev 的 3000 冲突；
  2. 减少攻击面，外部无法直接访问；
  3. 强制走服务名，网络拓扑更清晰。

如果确实需要调试，用临时端口映射或 docker compose exec，不要长期把内部服务暴露出去。

第 3 步：127.0.0.1:18081:80 的安全含义 ​

只绑回环地址时，同一 Wi-Fi 下的其他人访问 http://你的IP:18081 是连不上的。开发机经常连咖啡店 / 公司网络，这个细节能避免把本地服务暴露给整个局域网。

需要让同事访问时，再显式改成 0.0.0.0:18081:80，并确认没有敏感数据。

第 4 步：端口冲突怎么定位 ​

bash
docker compose -f examples/docker/07-network-volume/compose.yaml ps
lsof -iTCP:18081 -sTCP:LISTEN

如果启动时报 bind: address already in use：

  • 先看 ps，是不是上一次的容器还在；
  • 再看 lsof，是不是本地其他进程占用；
  • 不要直接 kill 不认识的进程，先确认它是什么。

第 5 步：命名卷的「首次复制」行为 ​

命名卷第一次挂到非空目录时，Docker 会把镜像里该目录的内容复制进卷。这常用于「镜像自带默认配置，卷里保存修改后的配置」。

bind mount 没有这个行为：宿主机目录为空，容器里就是空，镜像里的文件被遮住。排查「配置文件怎么没了」时先看挂载类型。

第 6 步：数据在什么时候消失 ​

操作命名卷数据bind mount 数据
docker compose stop保留保留
docker compose down保留保留
docker compose down -v删除保留（在宿主机目录）
docker rm -f 容器保留保留
docker volume rm删除不适用

生产环境执行 down -v 前必须确认：这个卷里是不是数据库。本章示例的卷可以随便删，但真实项目不能养成习惯。

第 7 步：卷的实际位置 ​

bash
docker volume inspect 07-network-volume_appdata --format '{{.Mountpoint}}'

在 Docker Desktop 里，这个路径位于 Linux 虚拟机内，宿主机不能直接 cd 进去。要备份就：

  • 用容器挂载卷并打包：docker run --rm -v 卷名:/data -v "$PWD":/backup alpine tar czf /backup/data.tgz -C /data .；
  • 或用服务自身的备份工具（pg_dump、redis-cli --rdb）。

本章不展开备份，第 09、12 章会涉及数据与密钥的处理。

常见坑与排查 ​

现象根因排查与修复
容器里访问 localhost:5432 失败容器内的 localhost 是容器自己改用服务名 postgres:5432，并确认在同一网络
ENOTFOUND api服务不在同一网络，或服务名写错docker network inspect 看成员；核对 compose 的 networks
ECONNREFUSED api:3000DNS 通了，但应用只监听 127.0.0.1应用监听 0.0.0.0；docker exec 里用 wget 验证
宿主机访问不到容器端口没写 ports，或只写了 EXPOSE加 ports；docker compose ps 看 PORTS 列
bind: address already in use宿主机端口被占用lsof -iTCP:端口；停掉冲突进程或换端口
端口映射写反host:container 顺序错记住冒号左边是宿主机；用 curl 验证
改了源码容器没变挂的是镜像内副本，不是 bind mountdocker inspect --format '{{json .Mounts}}' 核对
down -v 后数据库空了卷被删除这是预期行为；生产禁用 -v，并做独立备份
命名卷里旧数据「覆盖」了新镜像卷保留旧内容，首次复制只发生在空卷需要迁移时显式备份、清空、恢复
容器 IP 写死在配置里，重启后连不上容器 IP 会变永远用服务名
一个容器接多个网络，DNS 解析混乱多网络下同名服务可能有多条记录显式指定网络别名；避免同名服务跨网络
Windows / macOS 上卷权限不对虚拟化文件共享不保留 uid用命名卷存数据；或用固定 uid 运行

排查网络问题的顺序

先 docker compose ps 看服务在不在 → 再 docker network inspect 看是否同网 → 再 docker exec ... getent hosts 服务名 看 DNS → 最后才看应用日志。不要一上来就改网络配置。

企业级做法 ​

  1. 按信任边界划网络：前端、后端、数据层分网络；只有需要跨界的服务接两个网络。
  2. 内部服务不发布端口：数据库、缓存、内部 API 一律不写 ports；对外只暴露反向代理 / 网关。
  3. 开发绑定回环地址：127.0.0.1:端口:容器端口，避免把开发服务暴露到局域网。
  4. 数据用命名卷，代码用 bind mount：语义清晰，备份与迁移策略也不同。
  5. 数据库备份独立于 Docker：pg_dump / redis-cli --rdb 定时执行，存到对象存储；不要依赖「卷还在」。
  6. 禁止 down -v 进生产脚本：清理脚本要区分开发与生产，卷删除必须二次确认。
  7. 网络策略可审计：compose / Kubernetes manifests 里显式写网络，别依赖默认网络；变更走 review。

练习与验收标准 ​

练习

  1. 把 outsider 加入 backend 网络，重新跑脚本，观察第 4 步的结果变化。
  2. 把 web 的端口改成 0.0.0.0:18081:80，用 lsof 观察监听地址差异。
  3. 删除 appdata 卷后直接运行 reader，记录报错；再跑 writer → reader。
  4. 用 docker run --rm --network 07-network-volume_backend node:24-alpine node -e "fetch('http://api:3000/healthz').then(r=>console.log(r.status))"，验证临时容器也能加入既有网络。

验收标准（可逐条执行）

  • [ ] docker compose -f examples/docker/07-network-volume/compose.yaml ps 中 api 为 (healthy)，web 有 127.0.0.1:18081->80/tcp；
  • [ ] curl http://127.0.0.1:18081/ 返回 nginx 页面；
  • [ ] bash examples/docker/07-network-volume/scripts/network-check.sh 第 2 步返回 200，第 4 步返回 ENOTFOUND；
  • [ ] docker compose ... port api 3000 输出 :0；
  • [ ] reader 在 writer 退出后仍能读到 hello from writer；
  • [ ] 能解释 EXPOSE、ports、docker run -p 三者的区别；
  • [ ] 能说出 down 与 down -v 对命名卷的不同影响。
