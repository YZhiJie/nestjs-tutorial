本章目标 ​

读完并动手做完本章，你应该能：

  1. 说清一条 SQL 的逻辑执行顺序，知道为什么 WHERE 里不能直接用 SELECT 的别名；
  2. 用 SELECT / WHERE / ORDER BY / LIMIT 完成单表查询，并正确处理 NULL；
  3. 用 INNER JOIN、LEFT JOIN 和多表 JOIN 回答「谁买了什么」这类业务问题；
  4. 用 GROUP BY / HAVING / FILTER 做分组统计，并区分 WHERE 与 HAVING；
  5. 用子查询、EXISTS、派生表表达「不存在」「高于平均」这类条件；
  6. 在真实 PostgreSQL 上执行六份 SQL 脚本，拿到可复现的输出。

概念与原理 ​

1. SQL 是声明式语言：你写「要什么」，优化器决定「怎么取」 ​

sql
SELECT c.name, count(*) AS order_count
FROM customers AS c
JOIN orders AS o ON o.customer_id = c.id
WHERE o.status = 'paid'
GROUP BY c.id, c.name
HAVING count(*) >= 1
ORDER BY order_count DESC
LIMIT 3;

这条 SQL 的执行顺序不是从上到下，而是：

text
FROM / JOIN  →  WHERE  →  GROUP BY  →  HAVING  →  SELECT  →  ORDER BY  →  LIMIT

由此得到三个直接结论：

  • WHERE 在分组之前执行，所以它不能引用聚合函数，也不能引用 SELECT 里刚定义的别名；
  • HAVING 在分组之后执行，所以它可以引用 count(*) 这类聚合结果；
  • ORDER BY 在 SELECT 之后，所以它能使用别名，也能使用原始列。

2. 四种 JOIN，先想清楚「一行代表什么」 ​

写法结果典型问题
INNER JOIN两边都匹配上的行每个订单对应的客户
LEFT JOIN左表全部行，右表没有就补 NULL哪些客户一单都没下
RIGHT JOIN右表全部行，左表没有就补 NULL很少用，通常调换表顺序写成 LEFT JOIN
FULL JOIN两边都保留对账时找「只在 A 表 / 只在 B 表」的差异

写 JOIN 之前先回答：结果里一行代表什么？ 一行是一个订单、一个订单行，还是一个客户？一行代表什么决定了 GROUP BY 的粒度，也决定了聚合数字会不会重复计算。

3. NULL 不是值，是「未知」 ​

SQL 使用三值逻辑：TRUE、FALSE、UNKNOWN。任何与 NULL 的比较结果都是 UNKNOWN，而 WHERE 只保留 TRUE 的行。所以：

sql
-- 永远查不到任何行
SELECT * FROM products WHERE stock = NULL;

-- 正确写法
SELECT * FROM products WHERE stock IS NULL;

COUNT(*) 统计行数，COUNT(column) 跳过该列为 NULL 的行。这个差别在 LEFT JOIN 后特别明显：没有订单的客户，count(o.id) 是 0，而 count(*) 是 1。

4. 聚合的粒度由 GROUP BY 决定 ​

GROUP BY category 之后，每一行代表一个品类；SELECT 里只能出现分组列或聚合函数。PostgreSQL 允许按主键分组后引用同表其他列（函数依赖），但跨数据库时不要依赖这个特性，把需要的列都写进 GROUP BY 更稳。

HAVING 是对分组结果的过滤，WHERE 是对原始行的过滤。能放在 WHERE 的条件不要放到 HAVING：越早过滤，参与分组的数据越少。

5. 子查询的三种形态 ​

形态例子注意
标量子查询(SELECT avg(price_cents) FROM products)必须只返回一行一列
IN / NOT INWHERE id IN (SELECT ...)NOT IN 遇到 NULL 会整体变 UNKNOWN，优先用 NOT EXISTS
EXISTSWHERE NOT EXISTS (SELECT 1 ...)只判断有没有行，通常比 IN 更稳

相关子查询（子查询引用外层列）语义清晰，但可能对每一行执行一次。数据量大时，JOIN + GROUP BY 往往更容易被优化器改写，第 06 章会用执行计划对比。

6. 标识符、字符串与类型 ​

  • 不加引号的标识符在 PostgreSQL 里会被折叠成小写：SELECT Name FROM Customers 等价于 select name from customers；
  • 字符串用单引号，双引号是标识符："name" 是列名，'name' 是字符串；
  • 整数相除会截断：7 / 2 得 3，要小数就写 7 / 2.0 或 7::numeric / 2；
  • 金额用整数分存储，展示时再除 100，避免浮点误差。

最小可跑示例 ​

示例目录 examples/database/02-sql-basics/，用四张表覆盖一对多与多对多。表结构如下：

sql
DROP TABLE IF EXISTS order_items;
DROP TABLE IF EXISTS orders;
DROP TABLE IF EXISTS products;
DROP TABLE IF EXISTS customers;

-- 客户：email 全表唯一，是「先查再插」之外的最后一道防线
CREATE TABLE customers (
  id         bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  email      text        NOT NULL UNIQUE,
  name       text        NOT NULL,
  city       text        NOT NULL,
  created_at timestamptz NOT NULL
);

-- 商品：价格用整数分，避免浮点误差；stock 不允许为负
CREATE TABLE products (
  id          bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  sku         text    NOT NULL UNIQUE,
  name        text    NOT NULL,
  category    text    NOT NULL,
  price_cents integer NOT NULL CHECK (price_cents >= 0),
  stock       integer NOT NULL DEFAULT 0 CHECK (stock >= 0)
);

-- 订单：状态用 CHECK 约束收敛，避免出现 'PAID' / 'paid' 两种写法
CREATE TABLE orders (
  id           bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  customer_id  bigint      NOT NULL REFERENCES customers (id),
  status       text        NOT NULL CHECK (status IN ('pending', 'paid', 'shipped', 'cancelled')),
  ordered_at   timestamptz NOT NULL,
  total_cents  integer     NOT NULL DEFAULT 0 CHECK (total_cents >= 0)
);

-- 订单行：订单删除时级联删除；商品被引用时不允许删除
CREATE TABLE order_items (
  id               bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  order_id         bigint  NOT NULL REFERENCES orders (id) ON DELETE CASCADE,
  product_id       bigint  NOT NULL REFERENCES products (id),
  quantity         integer NOT NULL CHECK (quantity > 0),
  unit_price_cents integer NOT NULL CHECK (unit_price_cents >= 0)
);

03-select.sql 覆盖单表查询的十个常用动作：

sql

-- 1. 查全部列：生产环境不要对宽表这么做，这里数据量小，便于观察
SELECT * FROM products ORDER BY id;

-- 2. 只取需要的列：少读列就少 IO，网络传输也更小
SELECT sku, name, price_cents FROM products ORDER BY price_cents DESC;

-- 3. WHERE：过滤在数据库里完成，不要把整表捞到应用内存再筛
SELECT sku, name, stock
FROM products
WHERE category = '外设' AND stock > 0
ORDER BY stock DESC;

-- 4. 模糊匹配：LIKE 区分大小写，ILIKE 不区分（PostgreSQL 特性）
SELECT name FROM products WHERE name ILIKE '%键盘%';

-- 5. 空值判断必须用 IS NULL / IS NOT NULL，不能用 = NULL
SELECT sku, name FROM products WHERE stock = 0;

-- 6. LIMIT + OFFSET：取第 2 页，每页 3 条（深分页问题在第 06 章）
SELECT id, name FROM products ORDER BY id LIMIT 3 OFFSET 3;

-- 7. 表达式与别名：金额分转元，保留两位小数
SELECT
  name,
  price_cents,
  round(price_cents / 100.0, 2) AS price_yuan
FROM products
ORDER BY price_cents DESC
LIMIT 3;

-- 8. CASE WHEN：把状态翻译成人类可读文案
SELECT
  id,
  status,
  CASE status
    WHEN 'pending'   THEN '待支付'
    WHEN 'paid'      THEN '已支付'
    WHEN 'shipped'   THEN '已发货'
    WHEN 'cancelled' THEN '已取消'
  END AS status_text
FROM orders
ORDER BY id;

-- 9. DISTINCT：去重前先想清楚「按哪几列唯一」
SELECT DISTINCT category FROM products ORDER BY category;

-- 10. IN / BETWEEN：范围条件比一串 OR 更易读
SELECT sku, name, price_cents
FROM products
WHERE category IN ('外设', '配件')
  AND price_cents BETWEEN 5000 AND 50000
ORDER BY price_cents;

逐步拆解 ​

第 1 步：JOIN 回答「谁买了什么」 ​

sql

-- 1. 一对一方向：每个订单补上客户姓名
SELECT
  o.id        AS order_id,
  c.name      AS customer_name,
  o.status,
  o.total_cents
FROM orders AS o
INNER JOIN customers AS c ON c.id = o.customer_id
ORDER BY o.id;

-- 2. 三表 JOIN：订单 → 订单行 → 商品
--    一行 = 一个订单里的一种商品
SELECT
  o.id             AS order_id,
  c.name           AS customer_name,
  p.name           AS product_name,
  oi.quantity,
  oi.unit_price_cents,
  oi.quantity * oi.unit_price_cents AS line_total_cents
FROM orders AS o
INNER JOIN customers AS c   ON c.id = o.customer_id
INNER JOIN order_items AS oi ON oi.order_id = o.id
INNER JOIN products AS p    ON p.id = oi.product_id
ORDER BY o.id, p.id;

-- 3. LEFT JOIN：找出「一个订单都没有」的客户
--    注意条件 o.id IS NULL 必须放在 WHERE；放到 ON 里语义会变
SELECT c.id, c.name, c.city
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id
WHERE o.id IS NULL;

-- 4. 对账：订单表里的 total_cents 是否等于订单行金额之和
--    不一致的行会被查出来，这是数据质量检查的常见写法
SELECT
  o.id AS order_id,
  o.total_cents,
  COALESCE(sum(oi.quantity * oi.unit_price_cents), 0) AS items_total_cents
FROM orders AS o
LEFT JOIN order_items AS oi ON oi.order_id = o.id
GROUP BY o.id, o.total_cents
HAVING o.total_cents <> COALESCE(sum(oi.quantity * oi.unit_price_cents), 0);

-- 5. 过滤 + JOIN：只统计已支付订单里的商品明细
SELECT
  o.id AS order_id,
  p.sku,
  p.name,
  oi.quantity
FROM orders AS o
INNER JOIN order_items AS oi ON oi.order_id = o.id
INNER JOIN products AS p ON p.id = oi.product_id
WHERE o.status = 'paid'
ORDER BY o.id, p.sku;

-- 6. 多对多：一个订单有多个商品，一个商品出现在多个订单里
SELECT
  p.name AS product_name,
  count(DISTINCT oi.order_id) AS order_count,
  sum(oi.quantity)            AS units_sold
FROM products AS p
INNER JOIN order_items AS oi ON oi.product_id = p.id
GROUP BY p.id, p.name
ORDER BY units_sold DESC, p.name;

第 2 步：LEFT JOIN 的条件放在 ON 还是 WHERE ​

sql
-- 正确：先 LEFT JOIN，再筛掉匹配上的行 → 剩下「没有订单的客户」
LEFT JOIN orders AS o ON o.customer_id = c.id
WHERE o.id IS NULL

如果把 o.status = 'paid' 写进 ON，语义是「只把已支付订单拿来匹配」，左表客户仍然全部保留；写进 WHERE 则会先补 NULL 再过滤，未支付客户会被干掉。条件位置不同，结果集不同，这是 JOIN 最常见的错误来源。

第 3 步：分组统计 ​

sql

-- 1. 全表聚合：一行结果
SELECT
  count(*)                    AS product_count,
  sum(stock)                  AS total_stock,
  round(avg(price_cents), 2)  AS avg_price_cents,
  min(price_cents)            AS min_price_cents,
  max(price_cents)            AS max_price_cents
FROM products;

-- 2. 分组聚合：一行 = 一个品类
SELECT
  category,
  count(*)                   AS product_count,
  sum(stock)                 AS total_stock,
  round(avg(price_cents), 2) AS avg_price_cents
FROM products
GROUP BY category
ORDER BY product_count DESC, category;

-- 3. 先 JOIN 再分组：一行 = 一个订单状态
SELECT
  o.status,
  count(*)          AS order_count,
  sum(o.total_cents) AS revenue_cents
FROM orders AS o
GROUP BY o.status
ORDER BY revenue_cents DESC;

-- 4. HAVING：对「分组后的结果」过滤，WHERE 不能引用聚合函数
SELECT
  category,
  count(*) AS product_count
FROM products
GROUP BY category
HAVING count(*) >= 3
ORDER BY product_count DESC;

-- 5. FILTER：条件聚合，比 CASE WHEN 更直观
SELECT
  c.name,
  count(o.id)                                        AS orders_total,
  count(o.id) FILTER (WHERE o.status = 'paid')       AS paid_orders,
  count(o.id) FILTER (WHERE o.status = 'cancelled')  AS cancelled_orders
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id
GROUP BY c.id, c.name
ORDER BY c.name;

-- 6. 多表聚合：消费金额 Top 客户
SELECT
  c.name,
  count(DISTINCT o.id) AS order_count,
  sum(oi.quantity * oi.unit_price_cents) AS gmv_cents
FROM customers AS c
INNER JOIN orders AS o      ON o.customer_id = c.id
INNER JOIN order_items AS oi ON oi.order_id = o.id
WHERE o.status <> 'cancelled'
GROUP BY c.id, c.name
ORDER BY gmv_cents DESC;

-- 7. ROLLUP：在分组结果后追加小计与总计
SELECT
  category,
  count(*)           AS product_count,
  sum(price_cents)   AS price_sum_cents
FROM products
GROUP BY ROLLUP (category)
ORDER BY category NULLS LAST;

-- 8. count(*) 与 count(列) 的差别：后者不统计 NULL
SELECT
  count(*)      AS rows_total,
  count(stock)  AS stock_not_null
FROM products;

第 4 步：子查询与反连接 ​

sql

-- 1. 标量子查询：只返回一行一列，可以出现在 SELECT 或 WHERE 中
SELECT
  name,
  price_cents,
  (SELECT round(avg(price_cents), 2) FROM products) AS avg_price_cents
FROM products
WHERE price_cents > (SELECT avg(price_cents) FROM products)
ORDER BY price_cents DESC;

-- 2. IN 子查询：下过「已支付」订单的客户
SELECT id, name
FROM customers
WHERE id IN (
  SELECT customer_id FROM orders WHERE status = 'paid'
)
ORDER BY id;

-- 3. EXISTS 反连接：没有下过任何订单的客户
--    EXISTS 只关心「有没有行」，不关心子查询返回什么列
SELECT c.id, c.name
FROM customers AS c
WHERE NOT EXISTS (
  SELECT 1 FROM orders AS o WHERE o.customer_id = c.id
)
ORDER BY c.id;

-- 4. 相关子查询：外层每一行都会让子查询执行一次
--    数据量大时通常不如 JOIN + GROUP BY，第 06 章会用执行计划对比
SELECT
  c.name,
  (SELECT count(*) FROM orders AS o WHERE o.customer_id = c.id) AS order_count
FROM customers AS c
ORDER BY order_count DESC, c.name;

-- 5. 派生表：先把订单行汇总成「每单金额」，再和订单表比较
SELECT
  o.id,
  o.total_cents,
  t.items_total_cents
FROM orders AS o
INNER JOIN (
  SELECT order_id, sum(quantity * unit_price_cents) AS items_total_cents
  FROM order_items
  GROUP BY order_id
) AS t ON t.order_id = o.id
WHERE o.total_cents <> t.items_total_cents;

-- 6. ANY / ALL：价格高于「配件」品类里任意一个商品
SELECT name, price_cents
FROM products
WHERE price_cents > ANY (
  SELECT price_cents FROM products WHERE category = '配件'
)
ORDER BY price_cents DESC;

「没有下过订单的客户」返回：

text
 id |      name
----+----------------
  5 | Barbara Liskov
  6 | Ken Thompson
(2 rows)

为什么不用 NOT IN？如果子查询结果里出现 NULL：

sql
-- 假设 orders.customer_id 允许 NULL，且有一行 NULL
SELECT * FROM customers WHERE id NOT IN (SELECT customer_id FROM orders);
-- 结果永远是空集：id <> NULL 是 UNKNOWN

NOT EXISTS 不受 NULL 影响，是更安全的反连接写法。

第 5 步：把查询结果映射到应用代码 ​

以 TypeORM 为例，三表 JOIN 可以用 QueryBuilder 表达（第 07 章会接入真实项目）：

ts
const rows = await this.orders
  .createQueryBuilder('o')
  .innerJoin('o.customer', 'c')
  .innerJoin('o.items', 'oi')
  .innerJoin('oi.product', 'p')
  .select(['o.id AS order_id', 'c.name AS customer_name', 'p.name AS product_name'])
  .where('o.status = :status', { status: 'paid' })
  .orderBy('o.id')
  .getRawMany();

getRawMany() 返回的是查询结果的原始行，不是实体；字段别名要和 SQL 对得上。复杂报表优先写 SQL，简单 CRUD 再用 Repository，这个边界第 07 章会展开。

常见坑与排查 ​

现象根因处理
WHERE 里用 SELECT 的别名报 column does not existWHERE 先于 SELECT 执行用原始表达式，或把条件放到 HAVING / 外层子查询
WHERE stock = NULL 查不到数据NULL 比较结果是 UNKNOWN用 IS NULL / IS NOT NULL
LEFT JOIN 后行数变多右表一对多，左表行被放大先确认粒度；必要时先在子查询里聚合再 JOIN
NOT IN 返回空集子查询结果含 NULL改用 NOT EXISTS，或在子查询里 WHERE col IS NOT NULL
GROUP BY 报列未聚合SELECT 里有非分组列把列加入 GROUP BY，或对它用聚合函数
count(*) 比预期大JOIN 放大行数用 count(DISTINCT o.id)，或先聚合再 JOIN
金额出现 0.30000000000000004用浮点存钱用整数分或 numeric，不要用 float / double
LIMIT 10 每次结果不一样没有 ORDER BY，顺序未定义明确排序字段，最好追加唯一列（如 id）
插入中文报编码错误数据库/连接不是 UTF-8PostgreSQL 用 UTF8；MySQL 用 utf8mb4
字符串比较大小写不一致= 区分大小写需要忽略大小写时用 LOWER() 或 ILIKE，并考虑索引

企业级做法 ​

  1. SQL 也进代码评审：复杂查询放在迁移/仓储层，和业务代码一起 review；不要散落在 Controller 的字符串拼接里。
  2. 参数化查询，永不拼接：WHERE email = $1，不要把用户输入拼进 SQL。ORM 的 QueryBuilder 也要用参数占位符。
  3. 分页必须稳定排序：ORDER BY created_at DESC, id DESC，否则翻页可能重复或漏行。
  4. 明确 NULL 语义：设计表时就决定「这个字段能不能为空」，查询时用 COALESCE 给默认值，不要让 NULL 悄悄流到前端。
  5. 聚合查询先小后大：先在子查询里把明细压成需要的粒度，再 JOIN，避免大表之间先笛卡尔式放大。
  6. 把对账查询固化成检查：订单总额与明细之和、库存与流水、支付与订单，都应该有可重复执行的校验 SQL。
  7. 命名统一：表名复数、列名蛇形、外键 <表>_id、时间以 _at 结尾；跨库迁移时能省大量映射代码。
  8. 不要在生产库跑 SELECT * 大表：列存/行存、网络传输、ORM 映射都会放大成本；只取需要的列。
