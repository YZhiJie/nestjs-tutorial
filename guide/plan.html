章节规划与目录结构 ​

全站 14 章与企业级专题的规划、目录结构与写作约定。

本页是整部教程的「设计图」，先于正文产出。它回答四个问题：写给谁、按什么切分、每章产出什么、哪些已经实现。

一、设计原则 ​

原则具体做法反例（本教程避免）
按功能切章，不按 API 罗列每章解决一个真实的工程问题，例如「请求进来后要经过哪些关卡」「@Controller 详解」「@Injectable 详解」各自成章
章节同构固定八段式：目标 → 原理 → 最小示例 → 拆解 → 常见坑 → 企业级做法 → 练习验收 → 延伸追问有的章节全是概念，有的章节全是代码
代码单一来源正文代码用 VitePress <<< 从 apps/api 真实文件导入文档里粘贴一份「示例代码」，仓库里另有一份
双线贯穿业务主线（用户 → 认证 → 缓存 → 队列 → BFF）+ 问题主线（生产里会怎么坏）每章一个互不相关的 demo
不写未核实结论版本号取实际安装值；性能与平台限制只写机制，不编数字「某方案快 10 倍」这类口头结论
完成度可见每页顶部有 成稿 / 骨架章 标记与课时；骨架章只写目标与落点，不装作已完成点进去是空白页或「TODO」

二、目标读者与前置 ​

  • 主读者：会 HTML/JavaScript，能看懂 async/await，但没写过 Node 服务端的人。
  • 次读者：写过 Express/Koa，想弄清 Nest 的分层、依赖注入与工程化的人。
  • 前置知识（第 0 章补齐，不单独成章）：Node 模块与进程、HTTP 报文、Promise、TypeScript 的 interface 与装饰器语法。
  • 不需要：数据库建模经验、Docker 经验、微服务经验——第 4、13 章从零讲。

业务域要讲清的机制代码落点实现状态

六、示例工程模块规划 ​

text
apps/api/src
├── main.ts                 # 启动入口（ESM 顶层 await）
├── setup-app.ts            # 全局管道/拦截器/过滤器/前缀（main 与 e2e 共用）
├── app.module.ts           # 根模块
├── config/                 # 配置聚合 + 环境变量校验
├── common/                 # 追踪 ID、日志、统一响应、全局异常
├── database/               # TypeORM 配置、迁移、种子与 CLI、连接错误提示
├── health/                 # 健康检查（liveness）与就绪检查（readiness）
├── redis/                  # Redis 连接与启动失败提示（缓存与队列共用）
├── cache/                  # 缓存存储抽象、Redis/内存驱动、响应缓存拦截器
├── queue/                  # BullMQ 队列、任务调度、刷新令牌清理任务
├── users/                  # 用户模块 + 令牌化的用户目录接口
├── audit/                  # 审计日志 + 与 users 的循环依赖示例
├── security/               # 密码哈希与刷新令牌工具（无框架依赖）
├── auth/                   # 登录、刷新轮换、登出、全局 Guard 与装饰器
├── bff/                    # 按端聚合、字段裁剪、聚合缓存、超时降级与下游 mock
├── orders/                 # 订单、库存、幂等键、状态机与库存盘点
├── realtime/               # SSE 订阅中心：房间、心跳、Last-Event-ID 回放
├── files/                  # 本地上传、魔数校验、归属鉴权与下载
├── webhooks/               # 回调验签、时间窗防重放、事件 ID 幂等
└── metrics/                # 进程内指标快照与 HTTP 中间件

后续章节按此路径增量扩展：payments/（企业级支付与对账）。

七、交付批次 ​

批次内容验收口径
第 1 批本页 + 站点骨架 + 第 01~03 章成稿 + 示例工程最小可运行版pnpm install → pnpm dev 接口可用；pnpm verify 通过
