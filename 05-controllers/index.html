05. 控制器 ​

对应漫画

本章配套四格漫画：EP.05 控制器与路由（含剧情回顾、知识点拆解、坑点清单与自测题）

本章示例：server/src/ch05-controllers（npm run start:ch05 → http://localhost:3005）

控制器是什么 ​

控制器负责处理传入的 HTTP 请求并向客户端返回响应。路由机制决定哪个控制器接收哪个请求。在 Nest 中，控制器 = 类 + 装饰器：

  • 类级 @Controller('users') 定义路由前缀；
  • 方法级 @Get() / @Post() / @Put() / @Delete() 等定义 HTTP 方法与路径；
  • 参数级 @Param() / @Query() / @Body() / @Headers() 提取请求数据。

处理器（handler）只需返回一个值——Nest 负责把它序列化成 JSON 并发送。返回 Promise 也可以，Nest 会自动等待决议。

代码实现 ​

下面这个控制器集中演示了常用装饰器全景：

ts
// 文件: server/src/ch05-controllers/users.controller.ts
// 控制器装饰器全景：路由参数 / 查询参数 / 请求体 / 请求头 / 状态码 / 重定向 / 异步处理
import {
  Body,
  Controller,
  Delete,
  Get,
  Headers,
  HttpCode,
  Param,
  ParseIntPipe,
  Post,
  Put,
  Query,
  Redirect,
} from "@nestjs/common";
import { UsersService } from "./users.service";

@Controller("users") // 类级路由前缀：本控制器所有路由都在 /users 下
export class UsersController {
  constructor(private readonly usersService: UsersService) {}

  // GET /users?keyword=ad —— @Query 读取查询字符串
  @Get()
  findAll(@Query("keyword") keyword?: string) {
    return this.usersService.findAll(keyword);
  }

  // GET /users/echo —— @Headers 读取请求头
  // 注意：静态路由要声明在 :id 之前，否则 "echo" 会被当成 id 匹配
  @Get("echo")
  echo(@Headers("user-agent") userAgent: string) {
    return { userAgent };
  }

  // GET /users/docs —— @Redirect 重定向（默认 302）
  @Get("docs")
  @Redirect("https://docs.nestjs.cn", 302)
  redirectToDocs() {
    // 返回值 { url } 可覆盖装饰器中的目标地址
  }

  // GET /users/async/list —— 处理器可以是 async，Nest 会等待 Promise 决议
  // 两段式静态路由同样要放在 :id 之前
  @Get("async/list")
  async findAllAsync() {
    return Promise.resolve(this.usersService.findAll());
  }

  // GET /users/:id —— @Param + ParseIntPipe 把字符串参数转成 number
  @Get(":id")
  findOne(@Param("id", ParseIntPipe) id: number) {
    return this.usersService.findOne(id);
  }

  // POST /users —— @Body 读取请求体；@HttpCode 覆盖默认状态码（POST 默认 201）
  @Post()
  @HttpCode(201)
  create(@Body("name") name: string) {
    return this.usersService.create(name);
  }

  // PUT /users/:id —— 更新资源，默认返回 200
  @Put(":id")
  update(@Param("id", ParseIntPipe) id: number, @Body("name") name: string) {
    return this.usersService.update(id, name);
  }

  // DELETE /users/:id —— 204 No Content：成功但不返回响应体
    @Delete(':id')
    @HttpCode(204)
    remove(@Param('id', ParseIntPipe) id: number) {
        this.usersService.remove(id);
    }
}

配套的服务（内存数据操作）：

ts
// 文件: server/src/ch05-controllers/users.service.ts
import { Injectable, NotFoundException } from '@nestjs/common';

export interface User {
    id: number;
    name: string;
}

@Injectable()
export class UsersService {
    private users: User[] = [
        { id: 1, name: 'admin' },
        { id: 2, name: 'demo' },
    ];

    findAll(keyword?: string): User[] {
        if (!keyword) return this.users;
        return this.users.filter((u) => u.name.includes(keyword));
    }

    findOne(id: number): User {
        const user = this.users.find((u) => u.id === id);
        if (!user) throw new NotFoundException(`用户 ${id} 不存在`);
        return user;
    }

    create(name: string): User {
        const user = { id: Math.max(...this.users.map((u) => u.id)) + 1, name };
        this.users.push(user);
        return user;
    }

    update(id: number, name: string): User {
        const user = this.findOne(id);
        user.name = name;
        return user;
    }

    remove(id: number): void {
        this.findOne(id);
        this.users = this.users.filter((u) => u.id !== id);
    }
}

请求对象装饰器速查 ​

装饰器对应 Express 对象
@Param(key?)req.params / req.params[key]
@Query(key?)req.query / req.query[key]
@Body(key?)req.body / req.body[key]
@Headers(key?)req.headers / req.headers[key]
@Ip()req.ip
@Req() / @Res()底层请求/响应对象（慎用，见坑点 3）

最佳实践与坑点 ​

  1. 静态路由声明在动态路由之前：@Get('echo') 若写在 @Get(':id') 之后，echo 会被当作 id 匹配（本章代码注释中特别标注）；
  2. 状态码语义化：POST 创建默认 201，删除成功用 @HttpCode(204)，不要随意返回 200 一把梭；
  3. 避免使用 @Res() 直接操作响应：一旦注入 @Res()，Nest 的标准响应处理（序列化、拦截器）即失效，除非确实需要流式输出等底层能力；
  4. 控制器保持轻薄：参数提取、调用服务、返回结果三段式，业务规则放服务层；
  5. 返回纯对象/数组即可，Nest 自动 JSON 序列化；返回字符串则按 text/html 发送（如第 2 章的 Hello NestJS!）。
