10. 拦截器 ​

对应漫画

本章配套四格漫画：EP.10 拦截器与 AOP（含剧情回顾、知识点拆解、坑点清单与自测题）

本章示例：server/src/ch10-interceptors（npm run start:ch10 → http://localhost:3010）

拦截器是什么 ​

拦截器（Interceptor）基于 AOP（面向切面编程） 思想，在控制器执行的前后插入横切逻辑。它能：

  • 在方法执行前/后绑定额外逻辑（日志、计时）；
  • 转换方法返回的结果（统一响应结构）；
  • 转换方法抛出的异常；
  • 根据条件完全覆盖方法行为（如缓存命中时直接返回）。

拦截器的核心是 RxJS：next.handle() 返回一个 Observable，处理器的返回值以流的形式经过 .pipe() 中的操作符。

text
拦截器A(前置) → 拦截器B(前置) → 控制器 → 拦截器B(后置) → 拦截器A(后置)
1

代码实现：三个经典拦截器 ​

日志计时 ​

ts
// 文件: server/src/ch10-interceptors/logging.interceptor.ts
// 拦截器：基于 RxJS，在处理器「前后」插入逻辑（AOP）
// 执行时机：守卫之后、管道之前进入；响应时按相反顺序离开
import { CallHandler, ExecutionContext, Injectable, NestInterceptor } from '@nestjs/common';
import { Observable, tap } from 'rxjs';

@Injectable()
export class LoggingInterceptor implements NestInterceptor {
    intercept(context: ExecutionContext, next: CallHandler): Observable<unknown> {
        const req = context.switchToHttp().getRequest<{ method: string; url: string }>();
        const start = Date.now();

        // next.handle() 返回处理器结果的 Observable；tap 观察流转而不修改它
        return next.handle().pipe(
            tap(() => {
                console.log(`[ch10] ${req.method} ${req.url} 耗时 ${Date.now() - start}ms`);
            }),
        );
    }
}

统一响应包装 ​

ts
// 文件: server/src/ch10-interceptors/transform.interceptor.ts
// 统一响应包装：{ code: 0, data, timestamp } —— 前后端约定常见写法
import { CallHandler, ExecutionContext, Injectable, NestInterceptor } from '@nestjs/common';
import { Observable, map } from 'rxjs';

export interface ApiResponse<T> {
    code: number;
    data: T | null; // 处理器返回 undefined 时归一化为 null
    timestamp: number;
}

@Injectable()
export class TransformInterceptor<T> implements NestInterceptor<T, ApiResponse<T>> {
    intercept(context: ExecutionContext, next: CallHandler<T>): Observable<ApiResponse<T>> {
        // map 把处理器的原始返回值包一层；异常不会经过 map（见第 12 章异常过滤器）
        return next.handle().pipe(
            map((data) => ({
                code: 0,
                data: data ?? null,
                timestamp: Date.now(),
            })),
        );
    }
}

超时控制 ​

ts
// 文件: server/src/ch10-interceptors/timeout.interceptor.ts
// 超时控制：处理器超过 N 毫秒未返回时，主动中断并抛出 408
import {
    CallHandler,
    ExecutionContext,
    Injectable,
    NestInterceptor,
    RequestTimeoutException,
} from '@nestjs/common';
import { Observable, TimeoutError, catchError, throwError, timeout } from 'rxjs';

@Injectable()
export class TimeoutInterceptor implements NestInterceptor {
    constructor(private readonly ms: number = 3000) {}

    intercept(context: ExecutionContext, next: CallHandler): Observable<unknown> {
        return next.handle().pipe(
            timeout(this.ms),
            catchError((err) => {
                // RxJS 的 TimeoutError → 转成 HTTP 语义明确的 RequestTimeoutException
                if (err instanceof TimeoutError) {
                    return throwError(() => new RequestTimeoutException(`请求超时（>${this.ms}ms）`));
                }
                return throwError(() => err);
            }),
        );
    }
}

注册（全局链）与追加（路由级） ​

APP_INTERCEPTOR 注册全局拦截器，链上顺序 = 注册顺序；TimeoutInterceptor 用 useFactory 演示带参实例化：

ts
// 文件: server/src/ch10-interceptors/app.module.ts
// APP_INTERCEPTOR 注册全局拦截器；链上顺序 = 注册顺序
import { Module } from '@nestjs/common';
import { APP_INTERCEPTOR } from '@nestjs/core';
import { LoggingInterceptor } from './logging.interceptor';
import { TransformInterceptor } from './transform.interceptor';
import { TimeoutInterceptor } from './timeout.interceptor';
import { UsersController } from './users.controller';

@Module({
    controllers: [UsersController],
    providers: [
        { provide: APP_INTERCEPTOR, useClass: LoggingInterceptor },
        { provide: APP_INTERCEPTOR, useClass: TransformInterceptor },
        { provide: APP_INTERCEPTOR, useFactory: () => new TimeoutInterceptor(3000) },
    ],
})
export class AppModule {}

控制器中 @UseInterceptors 可在路由级追加拦截器：

ts
// 文件: server/src/ch10-interceptors/users.controller.ts
import { Controller, Get, UseInterceptors } from '@nestjs/common';
import { LoggingInterceptor } from './logging.interceptor';

@Controller('users')
export class UsersController {
    // GET /users —— 命中全局拦截器链：Logging → Transform → Timeout
    @Get()
    findAll() {
        // 返回的裸数据会被 TransformInterceptor 包装成 { code, data, timestamp }
        return ['张三', '李四'];
    }

    // GET /users/slow —— 延迟 4s，超过 TimeoutInterceptor 的 3s 阈值 → 408
    @Get('slow')
    async slow() {
        await new Promise((resolve) => setTimeout(resolve, 4000));
        return '太慢了';
    }

    // GET /users/local —— @UseInterceptors 路由级追加一个拦截器（在全局链之外再执行）
    @UseInterceptors(LoggingInterceptor)
    @Get('local')
    localOnly() {
        return { tip: '本路由会打印两条日志：全局一条、路由级一条' };
    }
}

最佳实践与坑点 ​

  1. 异常不会经过 map 操作符：处理器抛错时流直接走错误通道，由异常过滤器兜底（第 12 章）——想在拦截器里处理错误用 catchError；
  2. map 里拿到的是「返回值」不是「响应」：此时响应尚未发送，可以安全地包一层结构；
  3. 超时阈值要能注入：把超时毫秒数做成构造参数（本章用 useFactory 传入 3000），不同环境给不同值；
  4. 拦截器执行顺序：全局 → 控制器级 → 路由级；前置按此顺序进入，后置逆序返回（洋葱模型）；
  5. ApiResponse<T> 的 data 要允许 null：处理器返回 undefined 时归一化为 null，避免泛型空值在严格模式下类型报错。
