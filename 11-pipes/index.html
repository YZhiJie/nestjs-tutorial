本章示例：server/src/ch11-pipes（npm run start:ch11 → http://localhost:3011）

管道是什么 ​

管道（Pipe）在控制器执行之前处理路由参数，承担两类职责：

  1. 转换（Transformation）：把输入数据转成期望的形式（字符串 "18" → 数字 18）；
  2. 校验（Validation）：数据不合法时抛出异常，请求根本到不了控制器。

管道实现 PipeTransform<T, R> 接口的 transform(value, metadata) 方法：入参是原始值与元数据，返回值会替换原参数传给控制器；抛出异常则由异常过滤器转成 4xx 响应。

代码实现 ​

内置管道组合 ​

Nest 内置 ParseIntPipe、ParseBoolPipe、ParseArrayPipe、DefaultValuePipe 等。管道可以串联，前一个的输出是后一个的输入：

ts
@Query('page', new DefaultValuePipe(1), ParseIntPipe) page: number
//            ① 缺省时补默认值 1        ② 再转成 number

自定义管道 ​

ts
// 文件: server/src/ch11-pipes/pipes/parse-id.pipe.ts
// 自定义管道：实现 PipeTransform，value 是入参原始值，metadata 描述它来自哪里
import { ArgumentMetadata, BadRequestException, Injectable, PipeTransform } from '@nestjs/common';

@Injectable()
export class ParseIdPipe implements PipeTransform<string, number> {
    transform(value: string, metadata: ArgumentMetadata): number {
        const id = Number(value);
        // 校验失败直接抛异常，异常过滤器会把它转成 400 响应
        if (!Number.isInteger(id) || id <= 0) {
            throw new BadRequestException(`参数 ${metadata.data ?? 'id'} 必须是正整数，收到：${value}`);
        }
        return id; // 返回值替换原参数，控制器拿到的已是 number
    }
}

DTO + class-validator ​

数据校验的「正规军」是 DTO + class-validator：规则用装饰器声明在类上，ValidationPipe 自动读取执行：

ts
// 文件: server/src/ch11-pipes/dto/create-user.dto.ts
// DTO（数据传输对象）：声明请求体的形状与校验规则
// class-validator 装饰器即规则；ValidationPipe 自动读取执行
import { IsEmail, IsInt, IsOptional, IsString, Max, MaxLength, Min, MinLength } from 'class-validator';

export class CreateUserDto {
    @IsString({ message: 'name 必须是字符串' })
    @MinLength(2, { message: 'name 至少 2 个字符' })
    @MaxLength(20)
    name!: string;

    @IsInt({ message: 'age 必须是整数' })
    @Min(0)
    @Max(150)
    age!: number;

    @IsOptional() // 可选字段：缺失时跳过后续规则
    @IsEmail({}, { message: 'email 格式不正确' })
    email?: string;
}

全局 ValidationPipe ​

ts
// 文件: server/src/ch11-pipes/main.ts
// 第 11 章「管道」入口
import 'reflect-metadata';
import { ValidationPipe } from '@nestjs/common';
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
    const app = await NestFactory.create(AppModule);

    // 全局 ValidationPipe：对所有 DTO 自动执行 class-validator 校验
    app.useGlobalPipes(
        new ValidationPipe({
            whitelist: true, // 剥离 DTO 中未声明的属性
            forbidNonWhitelisted: true, // 出现未声明属性直接 400（更严格，推荐开启）
            transform: true, // 按 DTO 类型自动转型（如字符串 "18" → number 18）
            transformOptions: { enableImplicitConversion: true },
        }),
    );

    const port = Number(process.env.PORT ?? 3011);
    await app.listen(port);
    console.log(`[ch11] pipes listening on http://localhost:${port}`);
}

bootstrap();

三个关键选项的含义：

选项行为
whitelist: true剥离 DTO 中未声明的属性（防止多余字段污染）
forbidNonWhitelisted: true出现未声明属性时直接 400（比静默剥离更严格，推荐）
transform: true按 DTO 声明的类型自动转型，处理器拿到的是 DTO 实例

控制器 ​

ts
// 文件: server/src/ch11-pipes/users.controller.ts
// 管道的两类用途：「转换」（transform）与「校验」（validate）
import { Body, Controller, DefaultValuePipe, Get, Param, ParseIntPipe, Post, Query } from '@nestjs/common';
import { CreateUserDto } from './dto/create-user.dto';
import { ParseIdPipe } from './pipes/parse-id.pipe';
import { UsersService } from './users.service';

@Controller('users')
export class UsersController {
    constructor(private readonly usersService: UsersService) {}

    // GET /users/list?page=2 —— 内置管道组合：默认值 + 转型
    @Get('list')
    list(@Query('page', new DefaultValuePipe(1), ParseIntPipe) page: number) {
        return { page, size: 10 };
    }

    // GET /users/5 —— 自定义管道 ParseIdPipe：非正整数直接 400
    @Get(':id')
    findOne(@Param('id', ParseIdPipe) id: number) {
        return this.usersService.findOne(id);
    }

    // POST /users —— DTO + 全局 ValidationPipe：
    // 不合法 → 400 + 逐字段错误信息；合法 → 自动转型为 CreateUserDto 实例
    @Post()
    create(@Body() dto: CreateUserDto) {
        return this.usersService.create(dto);
    }
}

最佳实践与坑点 ​

  1. 校验失败信息逐字段返回：ValidationPipe 默认把每个字段的所有违规信息放进 message 数组，前端可直接按字段展示；
  2. 自定义 message 用中文：class-validator 每个装饰器都接受 { message } 选项，面向中文用户的系统务必覆写默认英文文案；
  3. @IsOptional() 必须放最前面：可选字段缺失时跳过后续所有规则，放错位置会导致 undefined 也被校验；
  4. 全局管道 vs 参数级管道：DTO 校验用全局 ValidationPipe 一劳永逸；个别参数的特殊转换（如本站的 ParseIdPipe）用参数级；
  5. transform 开启后注意隐式转换：enableImplicitConversion: true 会按声明类型猜测转换，布尔/数字边界值建议显式写 @Type() 控制。
