07. 依赖注入 ​

对应漫画

本章配套四格漫画：EP.07 依赖注入进阶（含剧情回顾、知识点拆解、坑点清单与自测题）

本章示例：server/src/ch07-di（npm run start:ch07 → http://localhost:3007）

依赖注入回顾 ​

第 3 章已经建立了 DI 的基本认识：构造函数声明依赖，IoC 容器负责解析与注入。本章深入三个进阶主题：

  1. 循环依赖：A 依赖 B、B 又依赖 A 时如何破局；
  2. 可选依赖：依赖可能不存在时如何避免启动报错；
  3. ModuleRef：容器的编程式入口，运行时按需解析提供者。

循环依赖与 forwardRef ​

两个模块（或两个提供者）互相 import 时，Nest 无法决定先实例化谁，启动时会报：

Nest cannot create the AlphaService instance. ... potential circular dependencies
1

解法是 forwardRef()——把互相引用包成惰性求值的函数，两侧都要加。模块级循环在 imports 里用：

ts
// 文件: server/src/ch07-di/alpha/alpha.module.ts
// 模块级循环依赖：AlphaModule ⇄ BetaModule，必须用 forwardRef 打破「先有鸡还是先有蛋」
import { Module, forwardRef } from '@nestjs/common';
import { AlphaService } from './alpha.service';
import { BetaModule } from '../beta/beta.module';

@Module({
    // forwardRef 告诉容器：BetaModule 此刻可能尚未定义完，延迟到运行时再解析
    imports: [forwardRef(() => BetaModule)],
    providers: [AlphaService],
    exports: [AlphaService],
})
export class AlphaModule {}

提供者级循环在注入点用：

ts
// 文件: server/src/ch07-di/alpha/alpha.service.ts
import { Inject, Injectable, forwardRef } from '@nestjs/common';
import { BetaService } from '../beta/beta.service';

@Injectable()
export class AlphaService {
    constructor(
        // 提供者级循环引用同样要 forwardRef，且两侧都要加
        @Inject(forwardRef(() => BetaService))
        private readonly betaService: BetaService,
    ) {}

    whoAmI() {
        return 'alpha';
    }

    askBeta() {
        return `alpha 调用 beta.whoAmI() → ${this.betaService.whoAmI()}`;
    }
}

可选依赖与 ModuleRef ​

ts
// 文件: server/src/ch07-di/demo.controller.ts
import { Controller, Get, Inject, Injectable, Optional } from '@nestjs/common';
import { ModuleRef } from '@nestjs/core';
import { AlphaService } from './alpha/alpha.service';
import { BetaService } from './beta/beta.service';

// 未在任何模块注册的类：配合 ModuleRef 演示「运行时按需解析」
@Injectable()
export class LazyService {
    hello() {
        return '由 ModuleRef.get 在运行时解析得到';
    }
}

@Controller('di')
export class DemoController {
    constructor(
        private readonly alphaService: AlphaService,
        private readonly betaService: BetaService,
        private readonly moduleRef: ModuleRef,
        // @Optional()：依赖不存在时注入 undefined 而不是启动报错
        @Optional()
        @Inject('NOT_REGISTERED')
        private readonly notRegistered?: unknown,
    ) {}

    // GET /di/circular —— 循环依赖双方都能正常工作
    @Get('circular')
    circular() {
        return {
            alphaSays: this.alphaService.askBeta(),
            betaSays: this.betaService.askAlpha(),
        };
    }

    // GET /di/optional —— 未注册的依赖被安全地注入为 undefined
    @Get('optional')
    optional() {
        return { optional: this.notRegistered ?? null };
    }

    // GET /di/module-ref —— ModuleRef：容器的编程式入口
    @Get('module-ref')
    moduleRefDemo() {
        // 注意：LazyService 已在当前模块 providers 注册，只是代码路径上「按需获取」
        const lazy = this.moduleRef.get(LazyService, { strict: false });
        return { result: lazy.hello() };
    }
}

  • @Optional()：依赖未注册时注入 undefined，而不是让应用启动失败——适合「插件式」可选能力；
  • ModuleRef：容器的编程式入口，moduleRef.get(Token) 在运行时按需解析。常用于：按运行时条件选择实现、在静态方法/工具函数里取提供者、实现服务定位器模式（慎用）。

注入解析规则速查 ​

构造函数参数的解析顺序：

  1. 参数上有 @Inject(令牌) → 按令牌精确查找；
  2. 否则按参数类型（emitDecoratorMetadata 保留的元数据）查找同类型提供者；
  3. 标记了 @Optional() 且找不到 → 注入 undefined；
  4. 都找不到 → 启动期抛出 UnknownDependenciesException。

最佳实践与坑点 ​

  1. 循环依赖首先是设计信号：能重构就重构——把双方都依赖的部分抽成第三个模块是更干净的解法，forwardRef 是兜底手段而非首选；
  2. forwardRef 必须两侧成对出现：模块级、提供者级各自成对，只加一侧仍然报错；
  3. ModuleRef.get 默认 strict: true：只能取当前模块内注册的提供者；跨模块取值要传 { strict: false }，但此时拿到的是全局容器的实例（瞬态作用域语义会变化，详见源码注释）；
  4. ModuleRef 从 @nestjs/core 导入，不是 @nestjs/common——这是常见的导入错误；
  5. 优先构造函数注入：属性注入（@Inject() private readonly x: X 写在字段上）破坏了「构造完成即可用」的不变量，仅在没有构造函数的边角场景使用。
