08. 中间件 ​

对应漫画

本章配套四格漫画：EP.08 中间件（含剧情回顾、知识点拆解、坑点清单与自测题）

本章示例：server/src/ch08-middleware（npm run start:ch08 → http://localhost:3008）

中间件是什么 ​

中间件是请求处理管线的第一站：在路由处理器之前执行，可以访问 req、res 与 next()。它与 Express 中间件完全同构，能做任何事：执行代码、修改请求响应、结束请求、调用 next() 交给下一个中间件。

Nest 中有三种挂载方式：

方式适用场景依赖注入
类中间件（implements NestMiddleware）需要注入服务、按路由精确绑定✅
函数中间件无依赖、逻辑简单❌
全局中间件（app.use()）对所有路由生效❌

代码实现 ​

类中间件：请求追踪 ​

ts
// 文件: server/src/ch08-middleware/logger.middleware.ts
// 类中间件：实现 NestMiddleware，可注入依赖，可精确绑定到指定路由
import { Injectable, NestMiddleware } from '@nestjs/common';
import type { NextFunction, Request, Response } from 'express';
import { randomUUID } from 'node:crypto';

@Injectable()
export class LoggerMiddleware implements NestMiddleware {
    use(req: Request, res: Response, next: NextFunction) {
        // 为每个请求生成追踪 ID：写响应头，也挂到 req 上供下游使用
        const requestId = randomUUID();
        req.headers['x-request-id'] = requestId;
        res.setHeader('X-Request-Id', requestId);

        const start = Date.now();
        // res 的 finish 事件在响应发送完毕后触发
        res.on('finish', () => {
            console.log(`[ch08] ${req.method} ${req.originalUrl} ${res.statusCode} ${Date.now() - start}ms`);
        });

        next(); // 不调用 next() 请求会挂起
    }
}

函数中间件：耗时统计 ​

ts
// 文件: server/src/ch08-middleware/request-time.middleware.ts
// 函数中间件：无依赖注入需求时，一个普通函数即可
import type { NextFunction, Request, Response } from 'express';

export function requestTimeMiddleware(req: Request, res: Response, next: NextFunction) {
    const start = process.hrtime.bigint();
    // 坑点：响应头发送后（headersSent）不能再修改，
    // 因此包装 res.end，在真正写出响应前补写耗时头
    const originalEnd = res.end.bind(res) as (...args: unknown[]) => unknown;
    res.end = ((...args: unknown[]) => {
        const ms = Number(process.hrtime.bigint() - start) / 1e6;
        if (!res.headersSent) {
            res.setHeader('X-Response-Time', `${ms.toFixed(1)}ms`);
        }
        return originalEnd(...args);
    }) as Response['end'];
    next();
}

绑定：consumer API ​

模块实现 NestModule.configure()，用 consumer 声明绑定范围——这是 Nest 中间件与 Express 的关键差异：

ts
// 文件: server/src/ch08-middleware/app.module.ts
// 模块实现 NestModule.configure()，用 consumer API 声明中间件的绑定范围
import { MiddlewareConsumer, Module, NestModule, RequestMethod } from '@nestjs/common';
import { LoggerMiddleware } from './logger.middleware';
import { requestTimeMiddleware } from './request-time.middleware';
import { UsersController } from './users.controller';
import { OtherController } from './other.controller';

@Module({
    controllers: [UsersController, OtherController],
})
export class AppModule implements NestModule {
    configure(consumer: MiddlewareConsumer) {
        consumer
            // 多个中间件按声明顺序串行执行
            .apply(LoggerMiddleware, requestTimeMiddleware)
            // exclude 排除特定路由（支持方法与通配）
            .exclude({ path: 'users/excluded', method: RequestMethod.GET })
            // 绑定到整个控制器：UsersController 下的所有路由
            .forRoutes(UsersController);
        // 也可以按路由信息绑定：.forRoutes({ path: 'users', method: RequestMethod.ALL })
        // 或 .forRoutes('*') 绑定全部（等价于全局）
    }
}

全局中间件 ​

在入口文件直接 app.use()（Express 语义，对所有路由生效）：

ts
// 文件: server/src/ch08-middleware/main.ts
// 第 8 章「中间件」入口
import 'reflect-metadata';
import { NestFactory } from '@nestjs/core';
import type { NextFunction, Request, Response } from 'express';
import { AppModule } from './app.module';

async function bootstrap() {
    const app = await NestFactory.create(AppModule);

    // 全局中间件：直接在实例上 use，对所有路由生效（ Express 语义）
    app.use((req: Request, res: Response, next: NextFunction) => {
        res.setHeader('X-Powered-By', 'NestJS');
        next();
    });

    const port = Number(process.env.PORT ?? 3008);
    await app.listen(port);
    console.log(`[ch08] middleware listening on http://localhost:${port}`);
}

bootstrap();

控制器侧（读取中间件写入的 requestId）：

ts
// 文件: server/src/ch08-middleware/users.controller.ts
import { Controller, Get, Headers } from '@nestjs/common';

@Controller('users')
export class UsersController {
    // GET /users —— 命中绑定的中间件：响应带 X-Request-Id / X-Response-Time
    @Get()
    findAll(@Headers('x-request-id') requestId: string) {
        return { users: ['张三', '李四'], requestId };
    }
}

最佳实践与坑点 ​

  1. 响应头发送后不能再修改：res.on('finish') 回调里 setHeader 会抛 ERR_HTTP_HEADERS_SENT。本章的解法是包装 res.end，在真正写出前补写耗时头（见 request-time.middleware.ts 注释）；
  2. next() 必须调用（除非中间件主动结束请求），否则请求永远挂起；
  3. 类中间件才能注入依赖：需要在中间件里用 ConfigService、LoggerService 时，必须写成类并在模块 providers 注册；
  4. 中间件里拿不到路由元数据：此时还不知道请求会命中哪个控制器——需要反射读元数据的场景（鉴权、角色）请用守卫/拦截器；
  5. 绑定优先级：exclude 支持通配与方法过滤，注意路径写法不带前导 /（users/excluded 而非 /users/excluded）。
