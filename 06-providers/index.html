06. 服务与提供者 ​

对应漫画

本章示例：server/src/ch06-providers（npm run start:ch06 → http://localhost:3006）

提供者是什么 ​

提供者（Provider） 是 Nest 的核心概念：服务、仓库、工厂、工具类……任何「可被注入」的东西都是提供者。它的基本形态是用 @Injectable() 装饰的类，注册进模块的 providers 数组后，DI 容器就接管了它的实例化与注入。

四种注册方式 ​

providers: [LoggerService] 这种简写只是冰山一角。完整语法是 { provide: 令牌, useXxx: ... }，共四种形态：

ts
// 文件: server/src/ch06-providers/app.module.ts
// 提供者的四种注册方式：useClass（简写）/ useValue / useFactory / useExisting
import { Module } from '@nestjs/common';
import { APP_CONFIG, CONNECTION, LEGACY_LOGGER } from './tokens';
import { LoggerService } from './logger.service';
import { LifecycleService } from './lifecycle.service';
import { DemoController } from './demo.controller';
import { ProbeAService, ProbeBService } from './scopes/probe.service';
import { RequestScopeService, SingletonService, TransientService } from './scopes/instances.service';

@Module({
    controllers: [DemoController],
    providers: [
        // 1. 标准简写：等价于 { provide: LoggerService, useClass: LoggerService }
        LoggerService,
        LifecycleService,
        SingletonService,
        TransientService,
        RequestScopeService,
        ProbeAService,
        ProbeBService,

        // 2. useValue：直接注册一个现成值（配置对象、常量、mock）
        {
            provide: APP_CONFIG,
            useValue: { appName: 'providers-demo' },
        },

        // 3. useFactory：工厂函数，运行时计算；inject 声明工厂的依赖（按顺序注入）
        {
            provide: CONNECTION,
            useFactory: (config: { appName: string }, logger: LoggerService) => {
                logger.log('创建 CONNECTION（useFactory）');
                return { url: `db://${config.appName}:5432`, driver: 'postgres' };
            },
            inject: [APP_CONFIG, LoggerService],
        },

        // 4. useExisting：为已有提供者创建别名，两个令牌共享同一实例
        {
            provide: LEGACY_LOGGER,
            useExisting: LoggerService,
        },
    ],
})
export class AppModule {}

一个普通的 LoggerService（同时作为 useClass 与 useExisting 的演示对象）：

ts
// 文件: server/src/ch06-providers/logger.service.ts
import { Injectable } from '@nestjs/common';

// 标准提供者：类本身即是注入令牌（emitDecoratorMetadata 让容器拿到类型信息）
@Injectable()
export class LoggerService {
    private readonly prefix = '[app]';

    log(message: string) {
        console.log(`${this.prefix} ${message}`);
    }

    getPrefix() {
        return this.prefix;
    }
}

四种方式的选择指南：

方式适用场景
useClass（简写）常规服务，占 90% 场景
useValue配置对象、常量、测试 mock
useFactory实例需要运行时计算（连接串拼接、依赖其他提供者）
useExisting给已有提供者起别名（兼容旧代码、多令牌共享实例）

三种注入作用域 ​

ts
// 文件: server/src/ch06-providers/scopes/instances.service.ts
// 三种注入作用域的对照示例
import { Injectable, Scope } from '@nestjs/common';

let nextId = 1;

// DEFAULT（单例）：全应用共享一个实例 —— 绝大多数服务用它
@Injectable()
export class SingletonService {
    readonly instanceId = nextId++;
}

// TRANSIENT（瞬态）：每个「注入点」都会得到一个新实例
@Injectable({ scope: Scope.TRANSIENT })
export class TransientService {
    readonly instanceId = nextId++;
}

// REQUEST（请求级）：每个 HTTP 请求一个实例，请求结束即销毁
// 注意：注入了 REQUEST 级提供者的控制器/服务也会被级联提升为请求级
@Injectable({ scope: Scope.REQUEST })
export class RequestScopeService {
    readonly instanceId = nextId++;
}

用两个单例消费者做对照实验（为什么要两个类？见下方坑点 1）：

ts
// 文件: server/src/ch06-providers/scopes/probe.service.ts
// 作用域探针：两个「消费者类」各自注入同一瞬态提供者
// 瞬态语义（官方定义）：每个消费者类获得一个专属新实例；
// 注意两个坑点 —— ① 同一类内多个注入点共享同一实例（按消费者去重）；
// ② 注入请求级宿主时同请求内也会被去重。因此用两个单例消费者做对照
import { Injectable } from '@nestjs/common';
import { SingletonService, TransientService } from './instances.service';

@Injectable()
export class ProbeAService {
    constructor(
        readonly singleton: SingletonService,
        readonly transient: TransientService,
    ) {}
}

@Injectable()
export class ProbeBService {
    constructor(
        readonly singleton: SingletonService,
        readonly transient: TransientService,
    ) {}
}

统一观察出口——DemoController：

ts
// 文件: server/src/ch06-providers/demo.controller.ts
import { Controller, Get, Inject } from '@nestjs/common';
import { APP_CONFIG, CONNECTION, LEGACY_LOGGER } from './tokens';
import { LoggerService } from './logger.service';
import { LifecycleService } from './lifecycle.service';
import { ProbeAService, ProbeBService } from './scopes/probe.service';
import { RequestScopeService } from './scopes/instances.service';

interface Connection {
    url: string;
    driver: string;
}

@Controller('demo')
export class DemoController {
    constructor(
        // 标准注入：类型即令牌
        private readonly logger: LoggerService,
        private readonly lifecycle: LifecycleService,
        // 自定义令牌注入：useValue / useFactory / useExisting 注册的提供者
        @Inject(APP_CONFIG) private readonly config: { appName: string },
        @Inject(CONNECTION) private readonly connection: Connection,
        @Inject(LEGACY_LOGGER) private readonly legacyLogger: LoggerService,
        // 两个单例消费者中的瞬态对照组（见 scopes/probe.service.ts）
        private readonly probeA: ProbeAService,
        private readonly probeB: ProbeBService,
        // 请求级：本控制器被级联为请求级，每次请求都是全新 DemoController
        private readonly requestScope: RequestScopeService,
    ) {}

    // GET /demo/providers —— 四种注册方式的结果
    @Get('providers')
    getProviders() {
        return {
            config: this.config,
            connection: this.connection,
            // useExisting 是别名：与 LoggerService 指向同一实例
            legacySameAsLogger: this.legacyLogger === this.logger,
            loggerPrefix: this.legacyLogger.getPrefix(),
        };
    }

    // GET /demo/scopes —— 作用域对照（连续请求观察 id 变化）
    @Get('scopes')
    getScopes() {
        return {
            singletonA: this.probeA.singleton.instanceId, // 单例：处处相同
            singletonB: this.probeB.singleton.instanceId,
            transientA: this.probeA.transient.instanceId, // 瞬态：每个消费者类一个实例
            transientB: this.probeB.transient.instanceId,
            requestScopeId: this.requestScope.instanceId, // 请求级：每次请求都不同
        };
    }

    // GET /demo/lifecycle —— 生命周期钩子已执行的证据
    @Get('lifecycle')
    getLifecycle() {
        return { readyAt: this.lifecycle.getReadyAt() };
    }
}

生命周期钩子 ​

提供者可以实现三个常用钩子，框架在对应时机自动回调：

ts
// 文件: server/src/ch06-providers/lifecycle.service.ts
// 提供者生命周期钩子：按调用顺序演示
import { Injectable, OnApplicationBootstrap, OnModuleDestroy, OnModuleInit } from '@nestjs/common';

@Injectable()
export class LifecycleService implements OnModuleInit, OnApplicationBootstrap, OnModuleDestroy {
    private readyAt = 0;

    // 1. 所在模块的依赖解析完成后调用（适合初始化连接、预热缓存）
    onModuleInit() {
        this.readyAt = Date.now();
        console.log('[ch06] LifecycleService.onModuleInit');
    }

    // 2. 所有模块初始化完毕、应用开始监听前调用
    onApplicationBootstrap() {
        console.log('[ch06] LifecycleService.onApplicationBootstrap');
    }

    // 3. 收到关闭信号（需 app.enableShutdownHooks，见第 15 章）时调用
    onModuleDestroy() {
        console.log('[ch06] LifecycleService.onModuleDestroy');
    }

    getReadyAt() {
        return this.readyAt;
    }
}

最佳实践与坑点 ​

  1. 瞬态作用域的真实语义是「每个消费者类一个实例」：同一消费者类内多个注入点会去重共享同一实例；注入请求级宿主时同请求内也会去重。因此本章用 ProbeAService/ProbeBService 两个消费者类做对照，而不是在一个类里注入两次；
  2. REQUEST 作用域会级联传染：注入了请求级提供者的控制器/服务会被自动提升为请求级——每次请求都新建实例，性能敏感场景慎用；
  3. useFactory 的 inject 数组顺序必须与工厂函数参数一一对应；
  4. 令牌集中管理：字符串令牌散落在各文件容易拼写漂移，收拢到 tokens.ts（或使用 Symbol）；
  5. 初始化逻辑放 onModuleInit 而非构造函数：构造函数里做异步初始化（连数据库）无法被 await，是经典事故源。
